# Пилот №15: «Один источник — четыре тени»

Проверка идеи из [`../05-mozgovoy-shturm-arhitektura-i-vizualizaciya.md`](../05-mozgovoy-shturm-arhitektura-i-vizualizaciya.md#вопрос-1--про-два-пути-в-soz30-пункты-1-2):
«детализация» и «обобщение в алгоритм» — это не два документа, которые правят вручную
и которые неизбежно расходятся, а два **рендера одной структурированной модели**.
Тот же принцип, что уже работает в `sites/pomosch-po-domu` (`generate_all.py`:
markdown — источник истины, из него генерируются `database.json`, `prais.json`, CSV).

## Что здесь

| Файл | Роль |
|---|---|
| `haushalt-assistenz.source.json` | **Источник истины.** Структурированное описание услуги «Помощь по хозяйству»: целевая группа, правовые основания, стоимость по Leistungskomplex, шаги, точки решения, документы, глоссарий. Данные взяты из `soz30/persoenliches-budget/7 Haushalt Assistenz/01-Grundlagen-und-Konzept.md`. |
| `generate_views.py` | Генератор. Без внешних зависимостей (`json` + `pathlib`), запускается `python3 generate_views.py`. |
| `generated/*.md` | **Не редактировать вручную** — перегенерируются скриптом (та же конвенция, что у `database.json` в `sites/pomosch-po-domu`). |

## Четыре представления в `generated/`

1. **`01-detalnyj-tekst.md`** — подробный текст, по форме близкий к существующим
   документам `soz30` (таблицы правовых оснований и стоимости, глоссарий).
2. **`02-algoritm-diagramma.md`** — тот же порядок действий и та же точка решения
   («заявка одобрена?»), но в виде Mermaid-диаграммы (GitHub рендерит её нативно
   в превью markdown-файла).
3. **`03-legkaya-kartochka.md`** — лёгкая карточка в формате
   [`../02-adaptaciya-soz30.md`](../02-adaptaciya-soz30.md): те же шаги и глоссарий,
   но с пиктограммами и короткими фразами.
4. **`04-panel-stsenariy.md`** — сценарий канбан-доски для соцработника (не путать с
   панелью резидента из документа 03 — это её «родственник» для ведения заявок),
   переиспользующий визуальный язык и логику светофора из
   [`../demo/pult-nuzhd-demo.html`](../demo/pult-nuzhd-demo.html).

## Проверка вручную

```sh
cd docs/dostupnost-dlya-invalidov/pilot-15-odin-istochnik
python3 generate_views.py
```

Скрипт идемпотентен: повторный запуск с тем же источником даёт побайтово тот же
результат (никакой скрытой рандомизации/меток времени).

## Как добавить деталь, не «переписывая четыре документа»

Пример: нужно добавить региональную наценку ±20% (она реально упомянута в
`soz30`, в исходном документе). Правильный путь — не идти в `generated/` и не
редактировать все четыре файла вручную, а добавить поле, например
`"regional_variance": "±20%"`, в `haushalt-assistenz.source.json`, затем один раз
поправить нужный `render_*()` в `generate_views.py`, чтобы это поле подхватилось
в нужном представлении (обычно — в подробном тексте и в лёгкой карточке, но не
обязательно в диаграмме алгоритма — это иллюстрирует, что не каждое поле должно
попадать в каждое представление, и это тоже часть смысла подхода). Повторный
`python3 generate_views.py` обновит `generated/*.md`.

## Следующий шаг, если пилот приживётся

Если подход подтвердится на этом одном разделе — можно написать по такому же
`*.source.json` для каждого из 19+ разделов `soz30/persoenliches-budget/` (можно
даже полуавтоматически — вытащить таблицы стоимости и правовые ссылки из
существующих `.md` регулярными выражениями) и генерировать весь комплект
представлений разом для всей базы, а не только для «Haushalt Assistenz».
