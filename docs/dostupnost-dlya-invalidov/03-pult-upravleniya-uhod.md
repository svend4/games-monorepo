# Практика для `games-monorepo`: панель жизненно важных потребностей

## 0. Чем это НЕ является

Явно проговорим, потому что вопрос звучал именно так: это **не** симулятор жизни
(«Sims»), **не** менеджмент дома престарелых как игра, **не** Pflegeheim-стратегия.
Никаких очков, уровней, наград или «прокачки». Это рабочий инструмент — ближе к кнопке
вызова медсестры в больнице, чем к игре, но с гораздо более богатым словарём, чем одна
кнопка.

Из наработок студии (NEXUS, Crystal Collector) переиспользуется **только инженерия**:
чёткая отрисовка иконок на canvas/SVG в любом масштабе, паттерн «самодостаточная страница
без сборки», паттерн «anketa → структурированные данные» из `sites/pomosch-po-domu`. Игровой
дизайн — не переиспользуется вообще.

## 1. Кто пользуется

| Роль | Типичные ограничения | Что им нужно от интерфейса |
|---|---|---|
| **Резидент / клиент на дому** | Деменция, афазия, слабое зрение/слух, тремор, слабость | 1–2 касания до любой базовой потребности, крупно, без меню |
| **Персонал** | Работает быстро, часто на ходу, может держать телефон в одной руке | Мгновенно видеть, где и что нужно, без долгого чтения |
| **Родственники** | Хотят быть уверены, что всё хорошо, без вмешательства в уход | Минимум данных, максимум — «всё спокойно / нужна помощь» |

## 2. Экран резидента — набор потребностей

Пиктограммы (см. документ 01 — брать за основу ARASAAC/Metacom, не рисовать с нуля),
крупная сетка 3×4 или 4×3, один экран без прокрутки:

| Значок | Потребность | Комментарий |
|---|---|---|
| 🖐️ | Позвать персонал (общее) | Всегда первая кнопка, самая крупная |
| 🩹 | Боль | При нажатии — второй экран: ряд лиц Wong-Baker (документ 01, §3.4) для интенсивности |
| 🚻 | Туалет | — |
| 🍽️ | Еда / голод | — |
| 🥤 | Питьё / жажда | — |
| 🌡️ | Жарко / холодно | При нажатии — уточнение (жарко/холодно) |
| 💊 | Лекарства / плохое самочувствие | — |
| 🙂😐🙁 | Настроение | Три лица — как в Talking Mats (документ 01, §3.3) |
| 📞 | Позвонить родным | — |
| 🚶 | Хочу выйти / прогулка | — |
| 🔇 | Шум/свет мешает | Часто нужна деменции/аутизму — сенсорная перегрузка |
| 🆘 | Экстренно (SOS) | Отдельная, красная, доступна всегда, даже поверх других экранов |

Требования к каждой кнопке (Universal Design + WCAG, документ 01 §4–5):

- Минимум ~2,5 см на сторону (WCAG 2.5.5) — палец с тремором должен попадать надёжно.
- **Значок + слово всегда вместе** — никогда только цвет и никогда только иконка без
  подписи (иначе не работает для тех, кто эту конкретную иконку ещё не выучил).
- Постоянное расположение — кнопки не переставляются местами между сессиями
  (пространственная память компенсирует трудности с чтением).
- При нажатии — весь экран показывает **тот же значок увеличенным** + галочка +
  (если доступно в браузере) голосовое подтверждение через `SpeechSynthesis`
  («Персонал уже идёт»).
- Поддержка альтернативного ввода: фокус клавиатурой/переключателем (switch-scanning
  для тяжёлых двигательных нарушений) и стандартные ARIA-атрибуты для скринридера —
  как минимум разметка не должна этому мешать, даже если сканирование подключается
  внешним ассистивным устройством.

## 3. Экран персонала — очередь заявок

- Список по времени поступления, самое старое — сверху.
- Каждая строка: комната/резидент, значок потребности, сколько времени прошло.
- **Светофорная заливка времени ожидания** (документ 01 §3.5): зелёный < 2 минут,
  жёлтый < 5 минут, красный ≥ 5 минут — с автоматическим обновлением. Цвет **не
  единственный** сигнал — рядом всегда таймер числом.
- Кнопки «Принято» → «Выполнено», с фиксацией, кто и когда отреагировал (это же —
  основа для журнала качества, дублирующего идею `09_Qualitaet_Monitoring_Eskalation.md`
  из `soz30`, но в реальном времени, а не как ретроспективный документ).
- SOS всегда выделяется отдельно и не тонет в общем списке.

## 4. Персонализация как часть панели, а не апгрейд

При заселении/начале ухода — короткая анкета, ровно в духе `anketa-pamyatka.md` из
`sites/pomosch-po-domu`, только с картинками вместо чек-боксов:

- Какие из 12 значков этот человек точно узнаёт (проверяется один раз, по протоколу
  ISO 9186 из документа 01 §6) — непонятные значки на экране этого конкретного
  человека можно скрыть или заменить на слово.
- Предпочитаемый канал: только визуал / визуал + голос / только текст крупным шрифтом
  (для тех, кто, наоборот, пиктограммы не любит и предпочитает читать).
- Контакты для кнопки 📞, привычное время прогулки, известные триггеры сенсорной
  перегрузки для кнопки 🔇.

Это прямой аналог «This is Me» (документ 01 §3.6), но не бумажный, а встроенный в саму
панель — персонал открывает профиль резидента одним нажатием прямо из очереди заявок.

## 5. Технически — что в этом репозитории уже подходит

| Задача | Готовый паттерн в репозитории | Почему подходит |
|---|---|---|
| Чёткая крупная отрисовка значков на любом зуме | `games/crystal-collector/v2-isometric-2.5d` (Canvas 2D) | Тот же подход даёт чёткие контуры без блюра при увеличении — критично для слабовидящих |
| Самодостаточная страница без сборки, работает через `file://` | Все `*.html` в `sites/pomosch-po-domu`, `games/crystal-collector/v2-isometric-2.5d` | Планшет в комнате престарелых часто старый и офлайн — тяжёлые фреймворки не нужны |
| «Анкета → структурированные данные» | `sites/pomosch-po-domu/anketa-pamyatka.html` + `generate_data.py` | Тот же принцип для профиля резидента (раздел 4) |
| Реальный клиент-сервер для мультиустройства | `games/nexus/v1-2d-mmo` (PHP + MySQL, опрос каждые ~800 мс) | Ровно то, что нужно, чтобы заявка с планшета резидента появилась на телефоне персонала — паттерн уже реализован и обкатан в этом же репозитории |

Явно **не** переиспользуется: Three.js/WebGL (`v3-3d` версии NEXUS и Crystal Collector) —
для плоской панели с крупными кнопками 3D-рендер не даёт пользы, только лишний вес и
нагрузку на старые планшеты.

## 6. Этика и достоинство

- Дизайн — для **взрослых людей**: без мультяшности, без «детского» шрифта, спокойная
  палитра (см. также ограничение по цвету для деменции — избыточно яркие/пёстрые экраны
  могут провоцировать тревогу).
- Минимально необходимое отслеживание: фиксируется факт и время заявки, а не слежка за
  резидентом (никаких камер, никакого постоянного геотрекинга без явного согласия).
- Всегда есть словесный/голосовой запасной путь для тех, кто пиктограммы не любит — это
  надстройка, а не единственный способ попросить о помощи.
- Прозрачность для резидента: он должен понимать, кто и когда увидит его нажатие
  «настроение 🙁» — не должно ощущаться как скрытое наблюдение.

## 7. Демо

Рабочий, полностью офлайн макет — [`demo/pult-nuzhd-demo.html`](./demo/pult-nuzhd-demo.html):
экран резидента и экран персонала в одном файле, переключение вкладкой сверху. Все
данные — тестовые и хранятся только в localStorage браузера. Открывается прямо
двойным щелчком или через `http://localhost/01/docs/dostupnost-dlya-invalidov/demo/pult-nuzhd-demo.html`
при XAMPP-запуске, как остальные страницы репозитория.
