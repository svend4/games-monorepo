# Симулятор экологии — спека и псевдокод (нужды, хищник–жертва, миграции, сезоны)

## TL;DR
Детальная спека макро-симуляции живого мира из [NX-INN-002]: точные структуры данных и псевдокод для
**нужд** существ (голод/усталость/страх), **популяционной динамики хищник–жертва** (дискретная
Лотка–Вольтерра как проверенный кирпичик), **миграций** между зонами и **влияния сезонов** на рождаемость
и кормовую базу. Это «частный» (detailed) слой под «расширенным» [NX-INN-002] и бюджетной рамкой
[NX-SYS-005]: здесь — сигнатуры функций, численная устойчивость, граничные случаи и контракт данных, по
которым второй рой напишет `world_tick`.

## Краткое содержание
[NX-INN-002] ввёл живую экологию концептуально и дал каркасный псевдокод `worldTick → ecologyTick /
factionTick`, но оставил **четыре открытых технических вопроса**, явно делегированных «в [NX-SPEC-004]»:
(1) численная устойчивость дискретной Лотки–Вольтерры (clamp, шаг, защита от вымирания);
(2) обратимость «сворачивания» особей в агрегат без утечки баланса ([NX-SYS-005#стык-контуров]);
(3) хранить макро-состояние в JSON-поле БД или в нормализованных таблицах ([NX-INN-002#риски]);
(4) сжатие пропущенных мир-тиков при долгом отсутствии игрока.

Этот документ закрывает их для **экологического ядра** (фракции — отдельная спека, форвард-ссылка
[NX-SPEC-011]). Он фиксирует: формат агрегата зоны, формулы нужд и популяций с обоснованным выбором
численной схемы, алгоритм миграции как «перетекание давления», сезонные модификаторы (опора на
[NX-INN-011]), контракт событий EventBus и развилку схемы БД. Цель — отдать готовую к реализации
заготовку, которая **не взрывается численно**, **сходится с микро-слоем без потери баланса** и **дёшево
тикает офлайн** в духе северной звезды [NX-VIS-001] «дёшево инфраструктурно — дорого эмоционально».

## Расширенное содержание (общее)

Симулятор экологии живёт в **СЛОЕ 3 (systems)** по контрактам [NX-SYS-001]: он не держит ECS-сущности сам,
а читает/пишет **агрегаты зон** (макро) и материализует особей через `World` ([NX-SPEC-002]) только на
L4↔L5-переходе ([NX-SYS-005#семь-уровней]). Между системами общается только событиями ([NX-SPEC-001]).

Ядро состоит из четырёх подсистем, считающихся в строгом порядке за один **мир-тик** (`dt_world` ≈ 1–5 мин):

1. **Нужды (needs).** Голод/усталость/страх растут со временем; на макро-уровне хранится **среднее по
   популяции**, на микро — у каждой особи. Нужды — вход для поведения (utility-AI, [NX-SYS-005]) и для
   смертности (голод истощает популяцию).
2. **Хищник–жертва (population dynamics).** Дискретная Лотка–Вольтерра с ёмкостью среды на каждый узел
   трофической сети зоны. Это **бухгалтерия чисел**, а не симуляция особей.
3. **Миграции (migration).** Перетекание давления/особей между соседними зонами по градиенту «голодно
   здесь → сытно там» и при риске вымирания (реинтродукция из соседа).
4. **Сезоны (seasons).** Глобальные модификаторы рождаемости, кормовой базы и сна, привязанные к
   игровому календарю [NX-INN-011]: зима душит траву и поднимает голод хищников, весна — всплеск рождений.

Порядок важен: сезон задаёт коэффициенты → нужды растут → популяции считаются с этими коэффициентами →
миграция разруливает дисбалансы между зонами. Всё это — **макро**; микро-материализация (особи, их
индивидуальные нужды и поведение) — стык с [NX-SYS-005], а не предмет этой спеки по существу, но контракт
сворачивания (микро→макро) специфицируется здесь, потому что именно он замыкает баланс.

### Что эта спека добавляет к [NX-INN-002]
- Превращает каркасный псевдокод в **точные сигнатуры** с типами полей агрегата.
- Выбирает и обосновывает **численную схему** (полу-неявный шаг + clamp + субшаги при больших `dt`) против
  «NaN-взрывов и осцилляций до нуля», которых боялся [NX-INN-002#риски].
- Специфицирует **миграцию** (в [NX-INN-002] она была только упомянута как `migrationTick(...)`).
- Вводит **сезонный слой** (в [NX-INN-002] сезонов не было вовсе — это вклад данной спеки, опирающийся на
  [NX-INN-011]).
- Даёт **контракт обратимости** микро↔макро, который [NX-SYS-005#риски] пометил как обязательный.

## Детали и частные случаи

### Структуры данных (контракт)

Агрегат зоны — десятки чисел, как требует двухуровневая модель [NX-INN-002#двухуровневая-симуляция]:

```pseudo
ZoneAggregate = {
  zoneId,
  biome,                      // 'forest'|'tundra'|'steppe'... влияет на capacity/сезонную чувствительность
  neighbors: [zoneId...],     // граф зон для миграции
  species: {                  // узлы трофической сети, ключ — speciesId
    grass:  { pop, cap, needs:{hunger:0, fatigue:0, fear:0} },   // продуцент: cap = ёмкость биома
    deer:   { pop, cap, needs:{...} },
    wolf:   { pop, cap, needs:{...} },
    troll:  { pop, cap, needs:{...} }
  },
  lastTickAt,                 // время последнего мир-тика этой зоны (для ленивого/сжатого тика)
  playerPressure: {           // валидное давление игроков/эхо за окно (NX-INN-002, anti-cheat NX-REVIEW#sec3-4)
    deer: 0, wolf: 0, ...      // сколько особей выбито с прошлого тика
  }
}

SpeciesDef = {                 // data-driven, из JSON (NX-SYS-003); НЕ хардкод как нынешний eDefs[]
  id, trophicLevel,            // 0=продуцент(трава),1=травоядное,2=хищник,3=апекс
  preyOf: [speciesId...],      // кого ест (пусто у продуцента)
  growth,                      // r — собственный темп прироста (для продуцента/травоядных)
  predation,                   // a — коэффициент выедания добычи
  efficiency,                  // e — КПД конверсии съеденного в прирост хищника (e<1, второй закон термодинамики)
  death,                       // m — естественная смертность хищника
  hungerRate, fatigueRate,     // скорость роста нужд во времени
  seasonSensitivity            // {birth, forage, sleep} — насколько вид чувствителен к сезону
}
```

Замечание: текущий код держит врагов как захардкоженный `eDefs[]` в `EnemySystem.js` (5 особей, поля
`hp/atk/xp/g/spd`) и итерирует их в `tickEnemies(dt,t)`. `SpeciesDef` — это его эволюция в data-driven
форму ([NX-SYS-003]) плюс экологические поля (`trophicLevel`, `preyOf`, `growth`...), которых там нет.

### Численное ядро: какую схему Лотки–Вольтерры брать

Наивный явный Эйлер (как в каркасе [NX-INN-002]) при больших `dt_world` (минуты!) даёт ровно те патологии,
которых боялся [NX-INN-002#риски]: перелёт в отрицательные популяции, расходящиеся осцилляции, «вымер за
один тик». Спека фиксирует три страховки:

1. **Субшаги (substepping).** Большой `dt_world` режется на `K` внутренних шагов `h = dt_world / K` (например
   `K = ceil(dt_world / H_MAX)`, `H_MAX ≈ 0.05` мир-времени). Дёшево (десятки умножений), резко повышает
   устойчивость.
2. **Полу-неявная трактовка убыли.** Член выедания берём от **текущей** добычи, но списываем с добычи как
   `pop / (1 + a·pred·h)` (полу-неявно) — это безусловно неотрицательно, в отличие от `pop − a·pred·pop·h`,
   который может уйти ниже нуля.
3. **Жёсткий clamp в [0, cap]** после каждого субшага + **порог вымирания** `EXTINCT_FLOOR`: ниже него
   популяция не «тлеет» дробными числами, а ставится в очередь на реинтродукцию из соседа (миграция).

Логистический рост продуцента/травоядных — `r·pop·(1 − pop/cap)` — даёт ёмкость среды «бесплатно» и сам по
себе устойчив при субшагах.

### Нужды и смертность от голода
Нужды растут линейно во времени и **обнуляются событием насыщения** (особь поела / популяция «съела»
добычу). На макро голод популяции = функция от доступной добычи: если `eaten` за тик мал относительно
`pop`, средний `hunger` растёт, и часть популяции гибнет «сверх» естественной смертности (`starvation`).
Это замыкает причинность из [NX-INN-002]: «игрок выбил оленей → волки голодают → волки идут к деревне или
гибнут».

```
satietyGain   = eaten / max(1, pop)               // сколько добычи на голову
needs.hunger  = clamp(needs.hunger + hungerRate*dt - satietyGain, 0, 1)
starvation    = pop * STARVE_RATE * max(0, needs.hunger - HUNGER_DEATH_TH)
```

`fear` на макро — это «остаточный стресс зоны» (после набега хищников/игрока): поднимает миграционное
давление и временно снижает рождаемость, спадает со временем. `fatigue` на макро почти не нужен (это микро-
феномен «спать в логове ночью», [NX-INN-002] таблица), но хранится для бесшовного сворачивания микро→макро.

### Миграция как перетекание давления
Миграция — не телепорт особей, а **диффузия популяции по градиенту привлекательности** между соседними
зонами (классическая reaction–diffusion идея из матбиологии). Привлекательность зоны для вида =
`f(сытно ли, безопасно ли, не переполнено ли)`. Доля популяции `MIGRATE_FRAC` перетекает к более
привлекательному соседу. Отдельная ветка — **реинтродукция**: если в зоне вид ниже `EXTINCT_FLOOR`, а у
соседа выше «заповедного» резерва, небольшая группа возвращается (защита от необратимого вымирания,
[NX-INN-002#граничные-случаи]).

### Влияние сезонов (вклад этой спеки, опора на NX-INN-011)
Сезон — глобальный множитель, привязанный к игровому календарю [NX-INN-011] (день/ночь уже есть в
`DayNight.js`; сезоны — следующий, более крупный цикл). Модификаторы применяются к коэффициентам **до**
популяционного шага:

| Сезон | `cap` травы | рождаемость (`growth`) | голод хищников | сон/`fatigue` |
|---|---|---|---|---|
| Весна | ×1.2 | ×1.5 (всплеск окота) | ×1.0 | норма |
| Лето | ×1.0 | ×1.0 | ×1.0 | норма |
| Осень | ×0.9 | ×0.8 | ×1.1 | запас перед зимой |
| Зима | ×0.4 | ×0.3 | ×1.6 | спячка части видов |

`seasonSensitivity` у вида масштабирует эффект (тундровый вид меньше страдает от зимы). Сезоны делают
популяционные волны **наблюдаемыми и предсказуемыми** — это прямо питает «знание = сила» [NX-INN-004]:
игрок, знающий, что зимой волки голодны и спускаются к дорогам, получает преимущество.

### Граничные случаи
- **Долгое отсутствие → сжатый тик.** Если `now − lastTickAt > N·dt_world`, считаем **один**
  аппроксимирующий шаг с `dt = (now − lastTickAt)`, но с **повышенным `K`** (больше субшагов) ради
  устойчивости — это L6 «statistical» из [NX-SYS-005#сжатие]. Не гоняем N отдельных запросов.
- **Обратимость микро↔макро.** При сворачивании (`leaveZone`) число убитых/родившихся в микро **точно**
  вычитается/прибавляется к `pop`; инвариант: `Δpop_micro == Δpop_macro` за окно. Без этого «экология
  течёт» ([NX-SYS-005#риски]). Спека требует unit-теста на этот инвариант (тестов в проекте нет,
  [NX-REVIEW#sec3-5]).
- **Анти-чит.** `playerPressure` наполняется **только сервером** из валидных эхо ([NX-INN-002#риски],
  [NX-REVIEW#sec3-4]), не из клиентского отчёта «я убил 10000 оленей».
- **NaN-страховка.** После каждого тика — проверка `isFinite(pop)`; не-конечное значение откатывается к
  снимку начала тика и логируется (`sim:ecology:nan`), чтобы один баг не отравил БД для всех.

## Предложения и варианты реализации

Псевдокод — заготовка для второго роя; интеграция с архетип-ECS и бюджетом — по [NX-SPEC-002] и
[NX-SYS-005]. Подсистема живёт в слое 3 и общается через EventBus.

```pseudo
// ── Константы (data-driven из JSON, NX-SYS-003) ───────────────────────
H_MAX            = 0.05      // макс. размер внутреннего субшага
EXTINCT_FLOOR    = 2.0       // ниже — кандидат на реинтродукцию
RESERVE_FLOOR    = 8.0       // «заповедный» резерв соседа для донорства
MIGRATE_FRAC     = 0.10      // доля популяции, перетекающая за тик
STARVE_RATE      = 0.20
HUNGER_DEATH_TH  = 0.6       // порог среднего голода, выше которого начинается смертность

// ── ВХОД: один мир-тик по всему миру (сервер/таймер, офлайн) ──────────
function worldTick(world, now):
    season = seasonOf(world.calendar, now)          // NX-INN-011
    for zone in world.zones:
        dt = now - zone.lastTickAt
        if dt <= 0: continue
        ecologyTick(zone, dt, season)               // нужды + хищник-жертва
        zone.lastTickAt = now
    migrationPass(world, season)                    // межзонное перетекание (после локальных тиков)
    return digestSince(world, world.player)         // дайджест возвращения (NX-INN-002)

// ── Экология одной зоны: нужды + дискретная Лотка-Вольтерра ───────────
function ecologyTick(zone, dt, season):
    snapshot = copyPops(zone)                       // для NaN-отката
    K = max(1, ceil(dt / H_MAX))                    // субшаги для устойчивости
    h = dt / K
    for step in 1..K:
        stepEcology(zone, h, season)
    if not allFinite(zone): { restore(zone, snapshot); emit('sim:ecology:nan', {zoneId}) }
    clampAll(zone)
    reseedIfExtinct(zone)                           // ставит метки для migrationPass

function stepEcology(zone, h, season):
    grassCap = zone.species.grass.cap * season.grassCapMul
    // 1) продуцент — логистический рост (устойчив сам по себе)
    g = zone.species.grass
    g.pop = g.pop + g.def.growth * season.birthMul * g.pop * (1 - g.pop / grassCap) * h
    // 2) от низа к верху трофической сети
    for sp in zone.predatorChain:                   // отсортировано по trophicLevel возрастанием
        prey = aggregatePrey(zone, sp)              // суммарная доступная добыча (preyOf)
        // выедание (semi-implicit по добыче → всегда >= 0)
        contact = sp.def.predation * sp.pop
        eaten   = prey.pop * (1 - 1/(1 + contact*h))
        prey.pop = prey.pop - eaten
        // прирост хищника от съеденного (КПД e<1) минус естественная смертность
        sp.pop = sp.pop + (sp.def.efficiency*eaten - sp.def.death*sp.pop*h)
        // нужды и смертность от голода
        satiety = eaten / max(1, sp.pop)
        sp.needs.hunger = clamp(sp.needs.hunger + sp.def.hungerRate*h*season.hungerMul - satiety, 0, 1)
        starv = sp.pop * STARVE_RATE * max(0, sp.needs.hunger - HUNGER_DEATH_TH) * h
        sp.pop = max(0, sp.pop - starv)
    applyPlayerPressure(zone)                        // валидные эхо (NX-REVIEW#sec3-4), уменьшают pop
    decayFear(zone, h)

// ── Миграция: диффузия по градиенту привлекательности ────────────────
function migrationPass(world, season):
    deltas = {}                                      // накапливаем, применяем атомарно (без двойного счёта)
    for zone in world.zones:
        for sp in zone.species:
            for nb in zone.neighbors:
                aHere = attractiveness(zone, sp, season)
                aThere = attractiveness(world.zone(nb), sp, season)
                if aThere > aHere:
                    flow = sp.pop * MIGRATE_FRAC * (aThere - aHere)
                    deltas[(zone,sp)]  -= flow
                    deltas[(nb,sp)]    += flow
            // реинтродукция против вымирания (NX-INN-002 граничные случаи)
            if sp.pop < EXTINCT_FLOOR:
                donor = bestNeighborAbove(zone, sp, RESERVE_FLOOR)
                if donor: { deltas[(zone,sp)] += SEED_GROUP; deltas[(donor,sp)] -= SEED_GROUP }
    applyDeltas(world, deltas); clampWorld(world)

function attractiveness(zone, sp, season):
    food   = aggregatePrey(zone, sp).pop / max(1, sp.def.predation)   // сытно?
    safety = 1 - zone.species[sp].needs.fear                          // безопасно?
    room   = 1 - sp.pop / sp.cap                                      // не тесно?
    return W_FOOD*food + W_SAFE*safety + W_ROOM*room

// ── Сжатый тик при долгом отсутствии (L6, NX-SYS-005#сжатие) ──────────
function lazyCatchUp(zone, now):
    dt = now - zone.lastTickAt
    if dt > COMPRESS_THRESHOLD:
        ecologyTick(zone, dt, seasonAt(midpoint(zone.lastTickAt, now)))  // 1 шаг, повышенный K внутри
    else:
        ecologyTick(zone, dt, seasonOf(now))
    zone.lastTickAt = now

// ── Стык с микро: сворачивание особей обратно в агрегат ───────────────
// (материализация L5→L4 — в NX-SYS-005 enterZone; здесь обратная, балансирующая)
function leaveZone(zone):
    born = 0; killed = 0
    for e in zone.live:
        if e.dead: killed += 1
        // ... перенос индивидуальных needs в среднее по виду
    // ИНВАРИАНТ: Δpop_micro == Δpop_macro (тест обязателен, NX-REVIEW#sec3-5)
    for sp in zone.species:
        sp.pop = clamp(sp.pop + bornOf(sp) - killedOf(sp), 0, sp.cap)
        sp.needs = avgNeeds(zone.live, sp)
    zone.live = []
```

**Контракт событий (вписывается в каталог EventBus, [NX-SPEC-001] / [NX-SYS-001#каталог-событий]):**
- `world:tick` `{tickId, dtWorld, now}` — emit сервером/таймером; слушают экология/миграция/сезоны.
- `ecology:pop:changed` `{zoneId, species, from, to, cause}` — emit после тика; слушает дайджест/журнал.
- `ecology:pressure` `{zoneId, species, killed, byEcho}` — emit боевой системой/эхо; вход в `playerPressure`.
- `ecology:extinct` `{zoneId, species}` / `ecology:reseed` `{zoneId, species, from}` — миграция/реинтродукция.
- `season:changed` `{from, to}` — emit календарём ([NX-INN-011]); слушает экология (пересчёт множителей).
- `sim:ecology:nan` `{zoneId}` — диагностика численного сбоя (откат к снимку).
- `world:digest` `{events[]}` — emit при входе игрока; слушает UI ([HUD.js]/[Overlay.js]).

**Развилка: где хранить макро-состояние (открытый вопрос из [NX-INN-002#риски]).**
- **A. JSON-поле в БД (рекомендуется для прототипа).** `world_state` как один JSON-блоб (`zones`,
  `species`, `lastTickAt`). Просто, ложится на нынешний `progress`-JSON-паттерн целевой схемы
  [NX-ARCH#sec8], не требует миграции из 2 текущих таблиц. Минус — не запросить «все зоны, где волки
  голодают» SQL-ом; непрозрачно для аналитики.
- **B. Нормализованные таблицы** `zones`, `zone_species (zone_id, species_id, pop, …)`, `seasons`. Чисто,
  запрашиваемо, FK с `ON DELETE CASCADE` (как целевая схема [NX-ARCH#sec8] и хвалит [NX-REVIEW#п.7]). Минус
  — больше схемы и миграций; избыточно, пока зон мало.
- **Рекомендация:** **A на прототипе** (один блоб, один `UPDATE` на мир-тик), миграция на **B**, когда зон
  станет десятки и понадобятся запросы/лидерборды по экологии. Обе ветки используют одну `worldTick()`.

**Развилка: где хранить численную схему.** Полу-неявный шаг (рекомендуется) против RK4 (точнее, но дороже
и избыточно для геймплейной достоверности) против чистого явного Эйлера (отвергнут — неустойчив при
минутных `dt`).

## Что нового и какие кирпичики
> Документ технический (`spec`), но численный выбор и сезонный слой нетривиальны — по духу [NX-META-001] §1
> фиксирую происхождение.

- **НОВОЕ (в рамках NEXUS):** не сама Лотка–Вольтерра, а её **превращение в дешёвый офлайн-движок
  геймплея** с тремя страховками устойчивости (субшаги + полу-неявная убыль + clamp/floor), сцепленный с
  **нуждами как причиной смертности** и **сезонами как наблюдаемым предсказуемым ритмом**, всё в формате
  агрегата на десятки чисел/зону. Сезонный слой — приращение поверх [NX-INN-002], которого там не было.
- **Источники идей:**
  - `c20-proven` — **модель Лотки–Вольтерры** (1920-е) и **логистический рост** (Ферхюльст, XIX в.):
    проверенная за век математика как игровой движок, а не декор.
  - `humanities` — **reaction–diffusion** и теория метапопуляций (миграция как диффузия по градиенту);
    экология трофических сетей (КПД конверсии `e<1` — второй закон термодинамики в пищевой пирамиде).
  - `folklore`/`medieval` — народные пищевые иерархии бестиария (тролль ест волка, волк — оленя) и
    сезонный крестьянский календарь (зимний голод, весенний окот) как источник сезонных коэффициентов.
- **Проверенные кирпичики (берём как есть):**
  - **Субстеппинг и полу-неявные схемы** — стандарт игровой физики против взрывов при больших `dt`.
  - **Существующий `DayNight.js`** — буквальный кирпичик под календарь; сезоны — его «старший» цикл.
  - **Существующий `eDefs[]`/`tickEnemies`** из `EnemySystem.js` — точка эволюции в data-driven `SpeciesDef`.
  - **Двухуровневая макро/микро-симуляция** из [NX-INN-002] и **LOD-бюджет** из [NX-SYS-005] — рамка, в
    которую этот движок вставлен.
- **Чего мало в других играх (или нет):** численно устойчивая Лотка–Вольтерра + нужды + миграции + сезоны
  как **единый офлайн-движок браузерной RPG на дешёвом периодическом бэкенде**. Обычно популяционная
  динамика такого рода — удел тяжёлых десктопных симуляций (Dwarf Fortress) или научных моделей, а не
  веб-игр, которые либо не имеют живого мира, либо «фейкают» его рандомом (как нынешний `WorldEvents.js`).

## Риски, открытые вопросы
- **Численная устойчивость на практике.** Полу-неявная схема устойчивее явной, но осцилляции хищник–жертва
  всё ещё могут «звенеть» при экстремальных коэффициентах. Нужны профильные тесты на сходимость — а тестов
  в проекте нет ([NX-REVIEW#sec3-5]); спека требует завести их вместе с реализацией.
- **Баланс коэффициентов = дизайн, не код.** `growth/predation/efficiency/death` определяют, «интересны»
  ли волны популяций или скучны/катастрофичны. Это итеративная настройка (data-driven JSON, [NX-SYS-003]),
  не выводится из формул.
- **Читаемость для игрока.** Симуляция, которую не видно, = «ничего не происходит» ([NX-INN-002#риски]):
  дайджест, следы (трупы, миграционные тропы, оголённые пастбища) и сезонные приметы обязаны делать
  причинность наблюдаемой.
- **Стоимость при росте зон/видов.** `migrationPass` — O(зоны × виды × соседи); при сотнях зон считать
  бюджет в [NX-SYS-005]; кандидат на Web Worker (развилка C там же).
- **Связь сезонов с эхо/реальным временем.** Привязывать сезоны к игровому календарю или к реальным датам
  (как [NX-INN-011] обсуждает) — открытый вопрос, решается совместно с [NX-INN-011].
- **Схема БД** (развилка A/B выше) — решение принять при росте числа зон.
