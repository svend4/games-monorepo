# Скриптовый слой для моддинга: Lua / JS-песочница / собственный DSL поверх data-файлов

## TL;DR
Дать сообществу писать не только **данные** (JSON-уровни, балансы), но и **поведение** — через встроенный скриптовый слой: безопасный Lua, изолированную JS-песочницу или маленький декларативный DSL, который компилируется в те же данные. Берём проверенный кирпичик игрового моддинга (Lua в WoW/Garry's Mod/Factorio) и пристёгиваем «крылышки» — связку с data-driven архитектурой [NX-SYS-003](../30-systems/NX-SYS-003-data-driven-design.md): данные говорят *что есть в мире*, скрипт-хуки говорят *как оно реагирует*, всё в одной capability-песочнице с детерминированным бюджетом времени.

## Краткое содержание
Чистый data-driven подход (всё — JSON/таблицы, движок интерпретирует) упирается в потолок: данными нельзя выразить *логику* — «при смерти этого моба заспавнить трёх мелких», «раз в полнолуние цены у торговца падают», «если игрок дважды отказал NPC — открыть скрытую ветку». Дать это сообществу, не открывая исходники движка, можно только **скриптовым слоем**. Документ разбирает три варианта (Lua-embed, JS-sandbox, собственный DSL), их interop с остальным монорепо (HTML/JS-клиент, PHP-бэкенд `nexus_api.php`, Python-генераторы, SQL, Markdown), и — главное — **безопасность исполнения**: песочница, capability-модель, детерминированный бюджет CPU/памяти, защита и на клиенте, и на сервере. Связан с [NX-SYS-003](../30-systems/NX-SYS-003-data-driven-design.md) (источник данных, поверх которого живут хуки) и [NX-INN-012](../20-innovation/NX-INN-012-community-modding.md) (видение пользовательского контента как столпа игры).

## Расширенное содержание (общее)

### Зачем вообще исполняемый слой поверх данных
Data-driven дизайн ([NX-SYS-003](../30-systems/NX-SYS-003-data-driven-design.md)) уже даёт сообществу огромную власть: можно добавить предмет, моба, уровень, перебалансировать числа — не трогая код. Это «колесо», которое мы не переизобретаем. Но у декларативных данных есть жёсткий потолок выразительности:

- **Данные описывают состояние, не процесс.** `{"hp": 100, "drops": ["gold"]}` — это «что», но не «при каком условии и в каком порядке».
- **Любая новая *логика* требует правки движка.** Хочешь «босс в фазе 2 меняет тактику» — либо движок заранее предусмотрел флаг `phase2_behavior`, либо мод невозможен.
- **Комбинаторный взрыв флагов.** Попытка выразить всю логику через флаги в данных превращает JSON в плохой язык программирования с `if`-ами, записанными как поля.

Решение, проверенное индустрией: **дать модам хуки на события, а в хуках — настоящий маленький язык**. Тогда:
- движок остаётся закрытым и стабильным;
- мод не «лезет в кишки», а подписывается на событие и возвращает решение;
- логика живёт там, где ей место — в коде мода, а не в раздутых данных.

### Философия «велосипед с крылышками»
**Колесо/автомобиль (не переизобретаем):**
- **Lua-моддинг** — отполированный 20+ лет паттерн: WoW (аддоны), Garry's Mod (целые игровые режимы на Lua), Factorio (контролируемый Lua с детерминизмом для мультиплеера), Roblox (Luau), Defold, LÖVE. Lua задуман как *embeddable extension language* — это его прямое назначение.
- **Object-capability security** — модель «нет глобального доступа, есть только переданные возможности» (E-language, Caja, SES). Проверенный способ запускать чужой код безопасно.
- **WASM-изоляция** — современный «колесо»: линейная память, нет доступа к хосту без явных импортов.
- **Event-driven хуки** — паттерн «движок зовёт мод по имени события», старый как сами плагины (Emacs hooks, jQuery `.on()`).

**Крылышки (новое измерение поверх):** мы не просто «встраиваем Lua». Новое — **сращивание скриптового слоя с data-driven слоем** [NX-SYS-003](../30-systems/NX-SYS-003-data-driven-design.md) в единый формат мода: один пакет содержит и декларативные данные (что добавить), и скрипт-хуки (как оно ведёт себя), и манифест возможностей (что мод вправе трогать). Плюс — **детерминированный бюджет** исполнения, чтобы мод не подвесил кадр, и **двойная граница доверия**: клиент исполняет хуки ради отзывчивости, но сервер ([NX-POLY-006](NX-POLY-006-php-role.md), `nexus_api.php`) считает их не более чем «предсказанием» и переисполняет/проверяет авторитетно. Это Формула-1 (детерминизм + sandbox + server authority) поверх давно изобретённого автомобиля (Lua-аддоны).

### Три кита выразительности модов
1. **Данные** ([NX-SYS-003](../30-systems/NX-SYS-003-data-driven-design.md), [NX-POLY-004](NX-POLY-004-shared-data-files.md)) — JSON/таблицы: сущности, числа, ссылки. *80% модов.*
2. **Скрипт-хуки** (этот документ) — Lua/JS/DSL, подписанные на события движка. *Логика и поведение.*
3. **Манифест возможностей** — что мод объявляет и что ему разрешено. *Граница безопасности.*

## Детали и частные случаи

### Контракт мода: единый пакет «данные + поведение + права»
Мод — это директория/архив с манифестом. Манифест связывает декларативную часть ([NX-SYS-003](../30-systems/NX-SYS-003-data-driven-design.md)) и исполняемую:

```json
// mods/lunar-merchant/mod.json
{
  "id": "lunar-merchant",
  "version": "1.0.0",
  "engineApi": "1.x",                 // semver контракта движка — мод переживает апдейты
  "data": ["entities/merchant.json", "balance/prices.json"],
  "scripts": ["hooks/merchant.lua"],
  "capabilities": {                   // object-capability: НИЧЕГО, кроме явно перечисленного
    "events": ["onDayNightChange", "onShopOpen"],
    "world": ["readEntity", "spawnEntity"],
    "rng": "seeded",                  // только детерминированный seed-RNG (см. мультиплеер)
    "net": false, "fs": false, "dom": false, "eval": false
  },
  "budget": { "cpuMsPerTick": 1.5, "memKb": 4096 }
}
```

Скрипт-хук получает **узкое, замороженное API**, а не глобальный доступ:

```lua
-- mods/lunar-merchant/hooks/merchant.lua
-- В песочницу проброшены ТОЛЬКО объекты из capabilities. Нет os, io, require, нет _G мира.

local Engine = ...   -- единственная переданная capability-таблица

Engine.on("onDayNightChange", function(ctx)
  -- ctx.phase: "day"|"night"|"full_moon"; ctx.rng — детерминированный
  if ctx.phase == "full_moon" then
    local m = Engine.world.readEntity("merchant_main")
    if m then
      Engine.world.patch(m.id, { priceMultiplier = 0.7 })  -- мутация ТОЛЬКО через API
    end
  end
end)

Engine.on("onShopOpen", function(ctx)
  if ctx.rng:chance(0.1) then            -- 10% на редкий товар, RNG воспроизводим
    Engine.world.spawnEntity("rare_relic", { shop = ctx.shopId })
  end
end)
```

Ключевое: хук не вызывает `os.time()`, не пишет файлы, не открывает сокеты, не видит чужие моды. Всё, что он может, — перечислено в `capabilities`. Нарушение = мод не загружается (статическая проверка) либо вызов кидает ошибку (рантайм-проверка).

### Безопасность исполнения — главная тема
Чужой код = недоверенный код. Три угрозы и ответы на них:

**1. Доступ к хосту (кража данных, порча состояния).**
- **Lua:** не давать `io`, `os`, `require`, `loadstring`/`load`, `dofile`, метатаблицы строк. Создавать **новое окружение** (`_ENV` в 5.2+/Luau) с белым списком функций. На JS-движке (Fengari) `_G` строится вручную — мод физически не имеет ссылок на хост.
- **JS-sandbox:** только в изоляте без ссылок на `window`/`globalThis`/`fetch`/`document`. Реалистично безопасно — лишь через **отдельный realm** (ShadowRealm/SES) или **WASM-движок JS** (QuickJS-через-WASM): тогда «побег» ограничен линейной памятью WASM. «Песочница» через `Function`/`with`/`Proxy` в том же realm — **дырявая, не считается безопасной**.
- **DSL:** самый безопасный — у языка просто *нет* конструкций доступа к хосту; интерпретатор знает только разрешённые операции.

**2. Исчерпание ресурсов (зависший цикл, OOM, «кадр умер»).**
- **Бюджет CPU:** в Lua — `debug.sethook` с инструкционным счётчиком (прерывание по N виртуальных инструкций); в WASM — *fuel/epoch interruption* (Wasmtime epoch, либо счётчик топлива). Превысил `cpuMsPerTick` → хук убит, мод помечен «нарушитель», движок едет дальше.
- **Бюджет памяти:** Lua — кастомный аллокатор (`lua_setallocf`) с лимитом; WASM — `maximum` страниц линейной памяти.
- **Защита от бесконечного цикла на клиенте:** хуки исполняются в **Web Worker** (отдельный поток), главный поток не виснет; зависший Worker можно `terminate()`.

**3. Жульничество в мультиплеере (мод-чит).**
- **Server authority.** Клиент исполняет хуки только для отзывчивости (предсказание). Сервер ([NX-POLY-006](NX-POLY-006-php-role.md)) — источник истины: критичные хуки переисполняются авторитетно либо их эффект валидируется. Клиентский результат — гипотеза, не факт. Перекликается с эхо-мультиплеером [NX-INN-003](../20-innovation/NX-INN-003-echo-multiplayer.md).
- **Детерминизм.** Любой RNG в хуке — только seed-RNG из `ctx.rng`. Это даёт воспроизводимость (как контролируемый Lua в Factorio) и делает рассинхрон детектируемым.

### Граничные случаи
- **Конфликт модов.** Два мода подписаны на `onShopOpen` и оба меняют цену. Решение: хуки — это **обработчики событий с приоритетом**, движок применяет их по порядку загрузки и логирует конфликт; `patch` — аддитивный/последний-побеждает по политике поля. Никаких прямых записей в общий объект.
- **API-версионирование.** `engineApi: "1.x"` в манифесте. Движок v1/v2/v3 ([NX-POLY-001](NX-POLY-001-language-per-role.md)) экспортирует *один и тот же контракт событий*, поэтому мод переносим между 2D/изо/3D клиентами — он говорит с контрактом, а не с рендером.
- **Горячая перезагрузка.** Скрипты — текст; на dev-сборке перезагрузка хука без рестарта (как Garry's Mod `lua_reload`). Прод — только подписанные/проверенные паки.
- **Кодировки и русский текст.** Манифесты и data-файлы в UTF-8 (как `database.json`); Lua-строки — байтовые, поэтому UI-тексты модов держим в data-слое, а не зашиваем в скрипт.

## Предложения и варианты реализации

### Таблица выбора скриптового движка

| Критерий | Lua (Fengari / wasmoon / Luau) | JS-sandbox (QuickJS-WASM / SES) | Собственный DSL |
|---|---|---|---|
| Порог входа моддера | средний (новый язык, но простой) | низкий (все знают JS) | низкий для узких задач |
| Выразительность | высокая (полный язык) | высокая | ограничена дизайном |
| Безопасность «из коробки» | хорошая при ручном `_ENV` | **опасна** без realm/WASM | **наилучшая** (нет опасных конструкций) |
| Изоляция ресурсов | hook-счётчик инструкций | fuel/epoch в WASM | тривиальна (свой интерпретатор) |
| Детерминизм для MP | отличный (Factorio-доказано) | хороший в WASM | полный контроль |
| Размер рантайма в браузере | ~200-300 КБ (wasmoon) | ~300-600 КБ (QuickJS-wasm) | ~0 (свой парсер) |
| Стоимость для нас | низкая (готовый движок) | низкая-средняя | **высокая** (пишем язык + тулинг) |
| Лучше всего для | поведение сущностей, ИИ-хуки | команды, знакомые с JS | триггеры/правила, балансные формулы |

**Рекомендация:** основной слой — **Lua через wasmoon/Fengari** (проверенный паттерн, embeddable by design, детерминизм). **DSL** — поверх, для самых частых и безопасных задач (триггеры событий, формулы баланса), компилируется в данные [NX-SYS-003](../30-systems/NX-SYS-003-data-driven-design.md). **JS-sandbox** — опционально и только в WASM-изоляте, не как «eval в окне».

### DSL: декларативные триггеры, компилируемые в данные
Для 60-70% поведенческих модов полный язык избыточен. Маленький DSL «когда → если → делай» закрывает их безопасно и читаемо нетехническими авторами:

```yaml
# mods/lunar-merchant/rules.nexdsl  (источник истины — текст, как Markdown в проекте)
rule: full_moon_discount
when: dayNightChange
if: phase == "full_moon"
do:
  - patch: { entity: merchant_main, field: priceMultiplier, value: 0.7 }

rule: rare_drop
when: shopOpen
if: rng.chance(0.1)
do:
  - spawn: { entity: rare_relic, at: $shopId }
```

Python-генератор ([NX-POLY-005](NX-POLY-005-python-role.md), контент-пайплайн [NX-SYS-002](../30-systems/NX-SYS-002-content-pipeline.md)) компилирует DSL → проверенный JSON или → Lua, валидируя capabilities на этапе сборки (codegen как interop, [NX-POLY-002](NX-POLY-002-codegen.md)):

```python
# tools/dsl/compile.py  — DSL в безопасное промежуточное представление
def compile_rule(rule: dict, allowed_caps: set[str]) -> dict:
    used = collect_capabilities(rule)            # какие действия трогает правило
    illegal = used - allowed_caps
    if illegal:
        raise ModSecurityError(f"{rule['rule']}: запрещённые возможности {illegal}")
    return {
        "event": rule["when"],
        "guard": parse_expr(rule["if"]),         # только белый список операторов
        "actions": [lower_action(a) for a in rule["do"]],
    }
# выход кладём как data-файл; движок исполняет интерпретатором правил, не eval-ом
```

### Архитектура исполнения (клиент + сервер) и interop

```pseudo
// === КЛИЕНТ (HTML/JS, games/nexus/shared) ===
// Хуки модов исполняются в Web Worker — изоляция потока + возможность terminate.
ModRuntime.load(mod):
    sandbox = createLuaSandbox(env = whitelist(mod.capabilities))   // нет io/os/require
    sandbox.setBudget(mod.budget.cpuMsPerTick, mod.budget.memKb)    // hook-счётчик + аллокатор
    sandbox.run(mod.scripts)                                        // регистрирует Engine.on(...)

Engine.emit(event, ctx):                          // движок дёргает подписчиков
    for hook in subscribers[event] sorted by loadOrder:
        try: hook.invokeWithBudget(ctx)           // прерывание при превышении бюджета
        catch BudgetExceeded | SandboxError:
            quarantine(hook.mod); log(...)         // мод-нарушитель отключается, кадр живёт

// === СЕРВЕР (PHP, nexus_api.php) — авторитет ===
// Клиентский результат хука — лишь предсказание. Сервер проверяет/переисполняет.
api.applyModAction(playerId, action):
    if not capabilityAllows(action.mod, action.kind): reject("cheat?")
    authoritative = revalidate(action, serverState)  // сервер считает истину
    persist(authoritative); broadcast(authoritative) // см. NX-POLY-003 (HTTP/JSON стык)
```

Interop-механизмы (как слой стыкуется с остальным монорепо, [NX-POLY-003](NX-POLY-003-interop.md)):
- **Общие data-файлы** ([NX-POLY-004](NX-POLY-004-shared-data-files.md)): манифест и данные мода — те же JSON, что читают JS/PHP/Python. DSL компилируется в эти же файлы.
- **HTTP/JSON** ([NX-POLY-003](NX-POLY-003-interop.md)): клиентские эффекты хуков отправляются на `nexus_api.php` как намерения; сервер валидирует и рассылает авторитетное состояние.
- **Codegen** ([NX-POLY-002](NX-POLY-002-codegen.md)): Python компилирует DSL → JSON/Lua на этапе сборки, статически проверяя capabilities.
- **WASM** ([NX-POLY-003](NX-POLY-003-interop.md#wasm)): сам Lua/JS-движок поставляется как WASM — это и есть граница изоляции в браузере.

## Что нового и какие кирпичики
- **НОВОЕ:** превращение data-driven слоя [NX-SYS-003](../30-systems/NX-SYS-003-data-driven-design.md) из **чисто декларативного** в **исполняемый**, но без потери его безопасности: данные = «что», скрипт-хуки = «как», манифест возможностей = «что разрешено» — **в одном пакете мода**. Плюс детерминированный бюджет и двойная граница доверия (клиент-предсказание / сервер-авторитет), делающие комьюнити-скрипты пригодными для мультиплеера. Новое измерение поверх классического Lua-моддинга = **capability-манифест + детерминизм + перенос мода между v1/v2/v3 через стабильный контракт событий**.
- **Источники:** `c20-proven` (Lua как embeddable extension language, 1993; object-capability security; Unix-принцип наименьших привилегий), `fantastic`/`folklore` (мир, который сообщество дописывает само — как живые мифы), `humanities` (DSL и манифест как **текст — источник истины**, в духе Markdown-доков проекта).
- **Проверенные кирпичики:** Lua-моддинг (WoW аддоны, Garry's Mod игровые режимы, Factorio детерминированный Lua, Roblox Luau), движки Fengari/wasmoon/QuickJS-WASM, object-capability модель (SES/Caja), WASM-изоляция и fuel/epoch-прерывание (Wasmtime), event-hook паттерн, seed-RNG для воспроизводимости.
- **Чего обычно нет (или редко) в играх:** связки скриптового моддинга **именно с data-driven слоем** в едином версионируемом контракте мода, переносимого между несколькими клиентами (2D/изо/3D), плюс серверной реавторизации хуков. Обычно моддинг — это либо «только данные», либо «Lua с почти полным доступом и доверием к клиенту».

## Риски, открытые вопросы
- **Безопасность — высокий риск.** «Песочница» легко оказывается дырявой (особенно JS в том же realm). Митигация: только проверенные движки в WASM-изоляции; аудит белого списка; никакого `eval`/`load` в проде; пентест перед открытием UGC.
- **Производительность.** Сотни модовых хуков на тик способны убить кадр. Митигация: жёсткий `cpuMsPerTick`, исполнение в Worker, ленивые подписки только на нужные события, профилировщик хуков.
- **Детерминизм vs гибкость.** Запрет «свободного» RNG/времени раздражает авторов, но необходим для MP. Открыто: где провести границу между «творческой свободой мода» и «детерминизмом для сервера».
- **Версионирование контракта.** Малейшее изменение событийного API ломает экосистему модов. Нужен строгий semver `engineApi` и слой совместимости — кандидат на отдельный спек [NX-SPEC-003](../40-specs/NX-SPEC-003-schema-and-codegen.md).
- **Открыто:** нужен ли единый магазин/реестр модов с подписью паков и репутацией авторов? Связано с видением [NX-INN-012](../20-innovation/NX-INN-012-community-modding.md).
- **Открыто:** LLM-NPC ([NX-INN-008](../20-innovation/NX-INN-008-llm-driven-npcs.md)) — должны ли скрипт-хуки иметь capability «спросить NPC-мозг», и как это бюджетировать (сетевой вызов внутри детерминированного тика — конфликт).

## Комментарии
Документ сознательно делит власть моддера на три уровня (данные → DSL → полный скрипт), чтобы 80% авторов остались в безопасном data/DSL-слое, а полный Lua получали только те, кому он нужен. Это снижает поверхность атаки. Возможна ветка `NX-CMT-###` о выборе Lua vs Wasm-плагинов (компонентная модель WASM как альтернатива Lua для «тяжёлых» модов).
