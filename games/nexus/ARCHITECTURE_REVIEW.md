## 1. Сильные стороны (плюсы)

1. **Правильный набор паттернов под заявленный масштаб.** EventBus (развязка систем), ServiceLocator (вместо россыпи глобалов), ECS (сущности как ID), ObjectPool (частицы/урон), StateMachine (состояния игры), фиксированный timestep. Скелет выбран корректно. *(разделы 1, 4)*
2. **GameLoop сделан по-настоящему правильно.** Аккумулятор фиксированного шага + `MAX_DT`-кламп против «спирали смерти» + `alpha` для интерполяции — канонический рабочий паттерн без багов. *(строки 691–708)*
3. **Каталог событий EventBus — лучшая часть документа.** Таблица «событие · payload · кто emit · кто слушает» читается как готовый контракт интеграции между системами. *(раздел 6, строки 871–901)*
4. **Чёткая слоистая модель с однозначным правилом зависимостей** «стрелка всегда вниз, нижние слои не импортируют верхние» — это исполнимый критерий для код-ревью. *(раздел 3, строка 326)*
5. **Конкретные правила вместо лозунгов:** «правило 400 строк», «нулевые глобальные переменные», naming-конвенции. Их можно проверять автоматически.
6. **Раздел производительности бьёт по правильным рычагам:** spatial hash вместо O(n²), LOD, frustum culling, InstancedMesh, бюджет кадра 16 мс. Направление верное. *(раздел 9)*
7. **Целевая SQL-схема продумана:** `UNIQUE` на `session_id`, FK с `ON DELETE CASCADE`, индексы под запросы, `progress` как JSON, денормализованный `leaderboard`. *(раздел 8)*
8. **Реальная безопасность БД в коде на месте:** все запросы через prepared statements с `PDO::ATTR_EMULATE_PREPARES => false`. SQL-инъекции закрыты. *(`nexus_api.php:26`)*
9. **Один настоящий перф-приём в коде есть и сделан грамотно:** частицы — единый `THREE.Points` с общими буферами (один draw call). *(`shared/engine/ParticleSystem.js`)*
10. **План миграции (раздел 10) верно указывает реальные точки боли** (`eDefs[]` в `EnemySystem.js`, флаг `journalOpen`) и расставляет их в разумном порядке.

## 3. Минусы по категориям

Severity: 🔴 critical · 🟠 high · 🟡 medium · ⚪ low.

### 3.1 Баги в «эталонных» листингах (разделы 4 и 9)

Листинги поданы как референс для копирования, поэтому баги в них тиражируются.

- 🟠 **EventBus.emit ломается при `off()`/`once()` внутри обработчика.** `emit` идёт `for`-циклом по живому массиву, а `off`/`once` пересоздают его через `.filter()` → часть слушателей пропускается. А `once()` снимает себя **гарантированно** при каждом срабатывании. На `entity:died` висит 4+ слушателя. *(строки 353–365 vs 384–402)*
- 🟠 **ObjectPool.release = O(n).** `indexOf`+`splice` на каждый возврат; в горячем цикле `FloatingText` это даёт **O(n²)** — обратное смыслу пула. *(строки 565–570, 608–614)*
- 🟠 **FrustumCuller пересоздаёт фрустум на каждую сущность.** `multiplyMatrices`+`setFromProjectionMatrix` внутри `isVisible()`, вызываемой в `forEach` по всем врагам. Оверхед сопоставим с самим AI, который пытались «пропустить». *(строки 1128–1138)*
- 🟡 **`entity:died`: payload-баг → `TypeError`.** Каталог (стр. 875) объявляет поле `tags`; пример `emit` (стр. 381) шлёт `{entityId, xp, gold, pos}` **без** `tags`; подписчик (стр. 386) делает `data.tags.has('enemy')` → упадёт. *(подтверждено двумя линзами)*
- 🟡 **StateMachine.back() корректен только один раз.** `transition()` всегда пушит в `_history` (включая стартовый `null` и back-переход) → накопление дублей, повторный `back` уводит обратно в `paused`. *(строки 631–644)*
- 🟡 **ObjectPool.releaseAll** мутирует `_active` во время обхода (`splice` в цикле) — O(n²) и хрупко. *(строки 572–574)*
- 🟡 **SpatialHash.query плодит GC-мусор** через `results.concat()` в двойном цикле; плюс нет стратегии обновления сетки (только `insert`/`clear`). *(строка 1094)*
- 🟡 **LOD подменяет `geometry` каждый кадр** без гистерезиса (дрожание на границе дистанций) и в обход штатного `THREE.LOD`; `highDetail/...` — необъявленные глобали, пример не скомпилируется. *(строки 1108–1118)*
- ⚪ **EventBus.once несовместим с `off(originalFn)`** — снять подписку можно только по ссылке на внутренний `wrapper`, которой у вызывающего нет → утечка подписок. *(строки 361–365)*

### 3.2 Производительность и масштаб

- 🟠 **Заявка «100+ зон, 500+ врагов, мультиплеер» ничем не подкреплена.** Фактически: 5 захардкоженных врагов (`eDefs`), 1 зона, «мультиплеер» = presence-polling с `LIMIT 50`. Ни spatial hash, ни InstancedMesh, ни frustum, ни LOD, ни fixed-timestep в коде нет.
- 🟠 **Бюджет «≤50 draw calls» не сходится с «500+ врагов».** Сейчас каждый враг = отдельный `THREE.Mesh` + HP-`Sprite` с `CanvasTexture` → ~1000 draw calls (×20 от лимита). InstancedMesh упомянут одной строкой и не покрывает HP-бары/тени/типы/анимацию. *(`EnemySystem.js`)*
- 🟡 **ECS `World.query` — O(n·m) каждый кадр** (`Object.keys` + вложенный цикл), без архетипов/индексов/кэша. Ровно та проблема, ради которой ECS и заводят. *(строки 483–495)*
- 🟡 **Раздел 9 умалчивает о ключевых рычагах:** AI-throttling по дистанции (хотя `aiCd` уже есть в коде!), geometry-merge статики зоны, time-slicing, Web Workers. Без них frustum culling не спасёт при всплеске видимых врагов.

### 3.3 Data-driven и контент-пайплайн

- 🟠 **Весь контент-пайплайн отсутствует:** нет папки `data/`, ни одного `.json` контента, ни `_schema.json`, ни `AssetLoader`. Данные захардкожены в JS (`eDefs[]`, `QUESTS[]`, `SHOP_ITEMS`, `EVENTS[]`). Без загрузчика «дизайнер правит JSON» физически невозможен.
- 🟡 **Схемы рассинхронизированы с механикой → вводят в заблуждение.** `dropTable` обещает `sword_iron` (chance 0.02), но движок дропает только `gold`/`potion`, а шансы захардкожены в `CombatSystem`. Дизайнер, правя `goblin.json`, не изменит в игре ничего.
- 🟡 **Локализация и целостность ссылок не заложены.** Имена («Гоблин») захардкожены в данных без i18n-ключей; связи по строковым id (`unlocks`, `targetZone`, `dropTable.item`) — без проверки целостности (опечатка = тихий битый ref).
- ⚪ **`$schema: "../_schema.json"`** резолвится мимо файла (он в той же папке `enemies/`, а не уровнем выше). Должно быть `"_schema.json"`.

### 3.4 Бэкенд, БД, безопасность

> Контекст: это XAMPP-прототип с пустым паролем `root`. Критичность ниже для локального демо, но документ позиционирует бэкенд как «production», поэтому оцениваю по его же заявке.

- 🔴 **Нет аутентификации.** `session_id` генерируется на клиенте (`'p'+Date.now()+Math.random()`) и кладётся в localStorage; сервер принимает любой присланный `session` как личность. Можно выдать себя за чужого, перезаписать/удалить его запись. *(`nexus_api.php:91–99, 142–146`)*
- 🔴 **Полное доверие клиенту по геймплею.** `hp`, `maxHp`, `level` приходят от клиента и пишутся как есть (clamp лишь до 9999/999). Тривиальный чит: `level:999`. Анти-чита нет. *(`nexus_api.php:79–99`)*
- 🟠 **БД-схема в документе ≠ реальность.** Документ: 5 таблиц, `pos_x/pos_z`, FK. Реально: **2 таблицы**, `x/y`, без FK, без `inventory/quest_progress/leaderboard`. Кто реализует `players.php` по документу — упадёт на несуществующих колонках.
- 🟠 **CORS `Access-Control-Allow-Origin: *`** в связке с отсутствием auth открывает CSRF-подобные злоупотребления и спам. *(`nexus_api.php:8`)*
- 🟠 **Нет rate limiting** (хотя документ обещает его в `Auth.php`), а `cleanup()` делает **два full-table `DELETE` на каждый запрос** (включая sync каждые 800 мс) — self-DoS под нагрузкой. *(`nexus_api.php:37–42, 53`)*
- 🟡 **Утечка деталей БД:** `PDOException->getMessage()` (фрагменты SQL/структуры) отдаётся клиенту. *(`nexus_api.php:159–162`)*
- 🟡 **Транспорт не тянет «MMO»:** HTTP-short-polling 800 мс, сервер не авторитетен, врагов на сервере нет. Это «co-op presence на 5–10 игроков», а не MMO. WebSocket из документа не существует.

### 3.5 Пробелы спецификации (чего нет вообще)

- 🟠 **Тестирование** — ни слова. Для ECS/сетевого sync/формул баланса невозможно ни верифицировать формулу урона, ни ловить регрессии при миграции.
- 🟠 **Сборка/модульность** — слепое пятно и противоречие: ~40 `<script>` в ручном порядке с глобальными IIFE не масштабируется до «1000+ предметов», нет ES-модулей/бандлера/tree-shaking/кеш-бастинга.
- 🟠 **Версионирование и миграции сейвов** — `SaveSystem` заявлен как факт, но без `schemaVersion` и `migrate()` первый же релиз сломает существующие сохранения.
- 🟠 **Безопасность как раздел и анти-чит** — отсутствуют, хотя есть живой PHP-бэкенд и leaderboard.
- 🟡 **Мобильный/тач-ввод и адаптивность** — `InputManager` обещает touch «единым API», но ни виртуального стика, ни брейкпойнтов; реальный v3 слушает только `keydown`.
- 🟡 **Обработка ошибок** — `AssetLoader.loadAll().then()` без `.catch`; нет реконнекта сети, деградации, ретраев.
- 🟡 **Управление зависимостями** — Three.js r128 с CDN без SRI-хеша и fallback: внешняя единая точка отказа.
- ⚪ **i18n и доступность (a11y)** — строки захардкожены по-русски; ни ключей перевода, ни aria.
- ⚪ **Нет CI/линта и Definition of Done** — «✅» проставлено по факту существования файла, а не соответствия архитектуре (что и породило главный разрыв).

## 4. Моё мнение

Документ написан человеком, который **знает, как надо**: набор паттернов, слои, data-driven, бюджет кадра — всё это грамотный, «взрослый» геймдев-инжиниринг, редкий для пет-проекта. Как **северная звезда** для рефакторинга монолита он отличный, и я бы его сохранил.

Но у него один системный порок, обесценивающий доверие: он **описывает мечту в настоящем времени**. Фраза «Фаза 1 — Уже сделано ✅» рядом с разделами, где код общается через `EventBus`, создаёт ложную картину — тогда как в реальности `shared/*.js` построен ровно на тех глобальных переменных и прямых вызовах, которые документ запрещает на первой странице. Это не мелочь: именно на стыке «документ говорит X, код делает not-X» теряются дни нового разработчика.

Второй по важности момент — **листинги поданы как эталон, но содержат реальные баги** (`emit` при `off`-внутри, `O(n)` pool, фрустум в цикле, `entity:died` без `tags`). Раз их предлагают копировать — они обязаны быть образцовыми.

И третий — **заявленный масштаб не обеспечен ни механизмом загрузки (40 `<script>`), ни сетью (polling), ни рендером (mesh-на-врага)**. «100+ зон / 500+ врагов / MMO» сегодня — это маркетинг шапки, а не свойство системы.

При этом честный `README.md`, который я добавил при сборке монорепо, уже наполовину закрывает проблему — осталось перенести эту честность **внутрь самого `ARCHITECTURE.md`**.

**Итог:** хороший документ-визия с завышенной самооценкой зрелости. Не выбрасывать — **отрефакторить под правду** и закрыть 5 инженерных пробелов. Это 1–2 дня работы над документом, которые сэкономят недели недопонимания.

## 6. Готовые правки кода (для копирования в раздел 4)

**EventBus.emit — итерировать по копии:**
```javascript
emit: function (event, data) {
  var list = _listeners[event];
  if (!list) return this;
  var snapshot = list.slice();           // защита от off()/once() внутри обработчика
  for (var i = 0; i < snapshot.length; i++)
    snapshot[i].fn.call(snapshot[i].ctx, data);
  return this;
}
```

**ObjectPool — O(1) release через swap-and-pop:**
```javascript
ObjectPool.prototype.get = function () {
  var obj = this._pool.length ? this._pool.pop() : this._factory();
  obj.__i = this._active.length;
  this._active.push(obj);
  return obj;
};
ObjectPool.prototype.release = function (obj) {
  var i = obj.__i, last = this._active.pop();
  if (last !== obj) { this._active[i] = last; last.__i = i; }
  this._reset(obj);
  this._pool.push(obj);
};
```

**FrustumCuller — строить фрустум один раз за кадр:**
```javascript
// один раз за кадр:
cMatrix.multiplyMatrices(camera.projectionMatrix, camera.matrixWorldInverse);
frustum.setFromProjectionMatrix(cMatrix);
// затем в цикле — только дешёвая проверка точки:
entities.forEach(function (e) {
  if (frustum.containsPoint(e.mesh.position)) AISystem.tick(e, dt);
});
```

**entity:died — класть `tags` в payload (иначе подписчик падает):**
```javascript
EventBus.emit('entity:died', { entityId: en.id, xp: en.xp, gold: en.gold, pos: en.pos, tags: en.tags });
```

**StateMachine — не пушить историю при back и при старте:**
```javascript
StateMachine.prototype.transition = function (name, data, _restoring) {
  if (!this._states[name]) throw new Error('Unknown state: ' + name);
  if (this._current && this._states[this._current].exit) this._states[this._current].exit();
  if (!_restoring && this._current) this._history.push(this._current);   // не пушим null и back-переход
  this._current = name;
  if (this._states[name].enter) this._states[name].enter(data);
};
StateMachine.prototype.back = function () {
  var prev = this._history.pop();
  if (prev) this.transition(prev, null, true);
};
```
