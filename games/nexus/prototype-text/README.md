# NEXUS — текстовый прототип (1D MUD-срез)

Рабочий прототип текстового/1D MUD-среза мира **NEXUS** на ядре **«Койне»** (субстрат
типизированных записей). В этом срезе играбельны два столпа из четырёх:

- **ЭХО** — оставлять и находить «вести» (записи типа `echo`), привязанные к комнате;
- **ЗНАНИЕ** — изучать факты и **декодировать руны**, которые читаются только при известном факте.

Текст здесь — не заглушка, а **прямой вид единого субстрата записей** (см. NX-VIS-004,
NX-INN-014): один и тот же мир можно «читать» (1D) и позже «видеть» (2D/3D), отрисовывая те же
записи.

---

## Принцип «современное-первым»

Ядро прототипа **современное**: чистые **ES-модули** (`import`/`export`), современный синтаксис,
**без сборщиков и без зависимостей**. Всё работает прямо в браузере.

**PHP — только опциональный адаптер за интерфейсом**, по умолчанию **выключен** и **не блокирует**
игру. Без MySQL/PHP всё работает целиком на клиенте (персист в `localStorage`). Серверный синк
(`server/echo.php`) можно подключить позже как один из адаптеров эхо.

---

## Запуск

ES-модули требуют протокол **http** (не `file://`). Прототип обслуживается локальным
**XAMPP/Apache**.

1. Запустите Apache в XAMPP.
2. Откройте в браузере:

   ```
   http://localhost/01/games/nexus/prototype-text/
   ```

> Открытие `index.html` двойным кликом (`file://`) **не сработает** — браузер заблокирует
> загрузку ES-модулей политикой CORS. Только через http.

### Опциональный PHP-синк эхо (по желанию)

По умолчанию **не требуется**. Чтобы включить общие (межсессионные/межигровые) эхо через сервер:

1. В XAMPP запустите **MySQL** и создайте БД (по умолчанию используется база `nexus`).
2. Адаптер `server/echo.php` сам создаёт таблицу `echoes` при первом обращении (если есть права).
3. В коде клиента подключите PHP-адаптер явно (он **не** активен по умолчанию):

   ```js
   import { echo } from './src/systems/echo.js';
   import { PhpEchoAdapter } from './src/systems/echo.js'; // опциональный адаптер
   echo.setAdapter(new PhpEchoAdapter('./server/echo.php'));
   ```

Если БД недоступна — адаптер возвращает аккуратный `{ error }`, а ядро продолжает работать на
локальном субстрате. PHP остаётся **необязательной надстройкой**, а не фундаментом.

## Как играть

Ввод — строкой в поле внизу, **Enter** отправляет команду. Парсер понимает русские и английские
глаголы.

| Команда (рус) | Англ | Что делает |
|---|---|---|
| `осмотреться`, `смотреть` | `look` | Описать текущую комнату (выходы, руны, число вестей) |
| `идти <направление>` | `go <dir>` | Перейти в соседнюю комнату (например `идти север`) |
| `читать <руна>` | `read <rune>` | Прочитать руну; расшифровка доступна только при известном факте |
| `изучить <факт>` | `learn <fact>` | Узнать факт (для теста ЗНАНИЯ; в полной игре факт даёт мир) |
| `оставить <текст>` | `echo <text>` | Оставить весть-эхо в текущей комнате |
| `вести` | `echoes` | Показать вести, оставленные здесь |
| `знания` | `lore` | Показать список известных фактов |
| `помощь` | `help` | Список команд |

**Игровая петля:** руна в комнате не читается «в лоб» — нужно сперва найти/изучить связанный факт,
затем `читать` её. Это и есть столп ЗНАНИЕ. Вести (`echo.leave`) сохраняются в субстрате и
находятся другими проходами через ту же комнату — это столп ЭХО.

## Карта файлов

Ядро современное (ES-модули); каждый файл — отдельный модуль с фиксированным контрактом
экспортов/импортов.

```
prototype-text/
├── index.html                  # терминальная страница: #log, #input, <script type="module">
├── README.md                   # этот файл
├── src/
│   ├── main.js                 # точка входа: интро + render старта + textui.start()
│   ├── core/
│   │   ├── eventbus.js         # bus: on/off/once/emit (emit по КОПИИ слушателей)
│   │   ├── ecs.js              # world: сущности/компоненты/query, индексы component→Set
│   │   └── substrate.js        # «Койне»: write/query/all/clear, персист localStorage
│   ├── world/
│   │   └── zone.js             # zones (4–5 комнат), state, player, getRoom; руны
│   ├── systems/
│   │   ├── knowledge.js        # knowledge: learn/knows/decode/known (столп ЗНАНИЕ)
│   │   └── echo.js             # echo: leave/find/setAdapter (столп ЭХО), адаптеры
│   └── ui/
│       └── textui.js           # textui: print/start/handle, MUD-парсер, render комнаты
└── server/
    └── echo.php                # ОПЦИОНАЛЬНЫЙ адаптер эхо (не ядро); MySQL, CORS, prepared
```

### Поток данных (вкратце)

- **`substrate.js`** — append-only журнал записей `{ id, type, author, t, place, payload, tags? }`.
  После каждого `write` шлёт `bus.emit('record:written', rec)`. Персист — `localStorage`
  (`nexus.substrate.v1`), фолбэк в память.
- **`echo.js`** — пишет/читает записи типа `echo` в субстрате (локальный адаптер по умолчанию);
  опционально — через `PhpEchoAdapter`.
- **`knowledge.js`** — хранит известные факты (`nexus.knowledge.v1`) и декодирует руны зоны.
- **`textui.js`** — единственный «рендерер» субстрата для 1D: парсит команды, рисует комнаты,
  подписан на `record:written` (живое обновление при появлении новых вестей).

## Привязка к проектным документам

Прототип реализует решения и контракты из проектной базы NEXUS
(`games/nexus/design/`):

**Видение и инновации**

- **NX-VIS-004** — *Мета-слой «Койне»*: единый субстрат типизированных записей; четыре столпа —
  линзы над ним. Здесь воплощены ядро-субстрат и линзы ЭХО/ЗНАНИЕ.
- **NX-INN-003** — *Эхо-мультиплеер*: записи, оставленные «поперёк времени/игроков». Столп ЭХО.
- **NX-INN-004** — *Прогрессия знанием*: знание как умение **декодировать и связывать** записи.
  Столп ЗНАНИЕ (руны читаются только при известном факте).
- **NX-INN-014** — *Текстовый/MUD-слой*: 1D-текст как первоклассный режим того же мира. Этот
  прототип и есть его «нулевое измерение» (1D → 2D → 3D).

**Технические спецификации (контракты)**

- **NX-SPEC-005** — *Эхо-протокол, реализуемый контракт*: порты/адаптеры, опциональный PHP за
  интерфейсом. Отражено в `echo.js` + `server/echo.php`.
- **NX-SPEC-006** — *Койне-субстрат, контракт API записей*: `write/query/all/clear`, типы записей,
  сменный персист-адаптер. Отражено в `substrate.js`.
- **NX-SPEC-007 … NX-SPEC-010** — последующие контракты слоя (зоны/руны, знание, текстовый UI,
  опциональный серверный синк), к которым привязаны соответствующие модули `world/`, `systems/`,
  `ui/` и `server/`.

> Контракты NX-SPEC-001 (*EventBus 2*) и NX-SPEC-002 (*ECS-архетипы*) лежат в основе
> `core/eventbus.js` и `core/ecs.js` соответственно.

## Замечания по архитектуре

- **Современное ядро, легаси не блокирует.** Игра полностью играбельна без сервера. PHP —
  отдельный, явно подключаемый адаптер; его отсутствие или сбой БД не ломают ядро.
- **Безопасность опционального адаптера.** `server/echo.php` использует prepared statements,
  CORS строго на `http://localhost` (не `*`), лимиты на длину/частоту и не отдаёт деталей
  исключений наружу.
- **Расширяемость.** Те же записи субстрата позже смогут отрисовывать 2D/3D-рендереры — без
  изменения ядра (см. NX-SYS-004, NX-VIS-004).
