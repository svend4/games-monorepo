# 09 — Аналитика, KPI и юнит-экономика

Навигация: [← LiveOps](08-liveops.md) | [README](README.md) | [Производство →](10-production.md)

Стек аналитики: Firebase Analytics (продуктовые события) + AppsFlyer (атрибуция, ad revenue, SKAN) + экспорт в BigQuery (когортный BI). Impression-level ad revenue — из MAX API ([06](06-monetization.md) §8).

---

## 1. Принципы трекинга

1. Каждое событие отвечает на конкретный продуктовый вопрос — событий «на всякий случай» нет.
2. Общие параметры всех событий: `session_id`, `lifetime_day`, `level_max`, `coins_balance`, `ab_groups`, `geo_tier`, `platform`.
3. Схема событий версионируется в репозитории (единый JSON-контракт, валидация в CI — см. [10](10-production.md) §3).
4. Пользовательская приватность: ATT-статус учитываем (opt-in ~27%), вся LTV-модель строится на контекстных и SKAN-данных, а не на детерминированной атрибуции.

## 3. Воронки

| Воронка | Шаги | Целевые проценты (база) |
|---------|------|--------------------------|
| FTUE | install → ftue_step 4 → step 9 → D1 return | 100% → 85% → 70% → 38% |
| Контентная | level_start(1) → complete(5) → complete(20) → complete(60) | 100% → 80% → 45% → 15% |
| Rewarded | ad_offer shown → accepted → completed | 100% → 30–35% → 85% (completion 80–90% — жанровая норма) |

| Interstitial-здоровье | триггер INT → показан (не capped) → закрыт без выхода из игры | show rate ~70%; выходы из app после INT <3% — алерт |

## 5. Юнит-экономика: LTV и окупаемость UA

### 5.1 Формулы

```
LT(N)   = 1 + Σ r(t), t = 1..N          — суммарные «дни жизни» на установку
LTV(N)  = LT(N) × ARPDAU_blended        — выручка на установку за N дней
ROAS(N) = LTV(N) / CPI                  — окупаемость когорты к дню N
Payback = min N: LTV(N) ≥ CPI
```

Кривая удержания (база): D1 38, D2 30, D3 25, D4 22, D5 19, D6 17, D7 15, D14 10.5, D30 6, D60 4, D90 3 (%). Между опорными точками — линейная интерполяция; проверка: LT7 = 1 + 1.66 = 2.66; LT30 ≈ 4.85; LT90 ≈ 7.43.

Проверка payback (база): нужен LT = CPI / ARPDAU = 0.90 / 0.15 = 6.0 дня; LT30 = 4.85, дни 31+ добавляют ~0.055–0.06 дня каждый → LT достигает 6.0 к **~дню 52** (LT60 = 6.34, LTV60 ≈ $0.95 > CPI). Оптимист: нужен LT = 0.85 / 0.22 = 3.86; LT7 = 3.06, дни 8–12 добавляют ~0.16–0.19 → **~день 12**.

### 5.2 Три сценария

| Параметр | Пессимист | **База** | Оптимист |
|----------|-----------|----------|----------|
| D1 / D7 / D30, % | 32 / 11 / 4 | **38 / 15 / 6** | 45 / 20 / 9 |
| LT7, дней | 2.33 | **2.66** | 3.06 |
| LT30, дней | 3.94 | **4.85** | 6.17 |
| LT90, дней | 5.62 | **7.43** | 10.1 |
| Blended ARPDAU | $0.10 | **$0.15** | $0.22 |
| LTV7 | $0.23 | **$0.40** | $0.67 |
| LTV30 | $0.39 | **$0.73** | $1.36 |
| **LTV90** | **$0.56** | **$1.10** | **$2.22** |
| CPI (blend 60% T1) | $1.10 | **$0.90** | $0.85 |
| ROAS D7 | 21% | **44%** | 79% |
| ROAS D30 | 36% | **81%** | 160% |
| **ROAS D90** | **51%** | **122%** | **261%** |
| Payback | нет (>180 дн.) | **~день 52** | ~день 12 |

Замечание к структуре: рыночный бенчмарк «89% рекламной выручки — в первые 7 дней» относится к средней по индустрии (крутая кривая оттока массового трафика). В нашей базовой модели кривая площе (D7 15% выше рынка), поэтому доля первой недели в LTV90 ≈ LT7/LT90 ≈ 36% — но управленческий вывод тот же: LTV7/CPI (D7 ROAS) — главный ранний предиктор, **порог D7 ROAS ≥ 40%** предсказывает окупаемость к D90 в базовой модели (44% базы → payback ~день 52).

### 5.3 Чувствительность (что двигает LTV сильнее всего)

| Рычаг | +10% к рычагу | Эффект на LTV90 |
|-------|---------------|------------------|
| D7 retention | 15% → 16.5% | +6–8% (через весь хвост LT) |
| Interstitial/DAU | 7.0 → 7.7 | +4.7% (+$0.007 к blended $0.15; риск: давление на ретеншен — только через A/B) |
| eCPM (гео-микс к T1) | +10% blend | +7% blended (ad-часть = 70% выручки) |
| Конверсия IAP | 2.2% → 2.4% | +3% |
