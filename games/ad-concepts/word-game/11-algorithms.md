# 11 — Приложение: алгоритмы контента (словари и генератор уровней)

Навигация: [← Производство](10-production.md) | [README](README.md) | [Симулятор экономики →](12-economy-sim.md)

Статус: нормативная спецификация контент-пайплайна для реализации в Проходе А ([10](10-production.md), раздел 3: «Node.js CLI-генератор (словари → паззлы → JSON-пакеты) в CI»). Все правила и номиналы — производные от [03](03-core-gameplay.md) §2 и §5–6; при расхождении глава 03 первична, это приложение обновляется синхронно. Псевдокод — структурированный TypeScript-подобный; целевая реализация — Node.js-скрипты в CI, клиентская часть (§4) — Phaser 3 + TypeScript.

Инварианты уровня документа:

- **INV-W1 (составимость):** каждое слово сетки и каждое бонус-слово уровня составимо из мультимножества букв колеса; каждая буква используется не чаще её кратности на колесе ([03](03-core-gameplay.md) §2.1).
- **INV-W2 (кроссвордность):** каждый максимальный ортогональный ран ≥ 2 клеток — ровно одно целевое слово; сетка связна; bounding box ≤ 9×9 ([03](03-core-gameplay.md) §2.1).
- **INV-W3 (двусловарность):** слова сетки ⊆ словаря генерации; бонусные слова валидируются по словарю валидации; BLACK-список не встречается нигде, GREY-список — никогда в сетке ([03](03-core-gameplay.md) §2.3, §5.1).
- **INV-W4 (детерминизм):** уровень полностью определяется своим JSON (≤ 2 КБ); генерация воспроизводима из сида; версия словаря пиннится в пакете уровней ([03](03-core-gameplay.md) §7).
- **INV-W5 (офлайн):** клиент ничего не генерирует и не ходит в сеть для валидации — DAWG словаря валидации лежит в бандле ([03](03-core-gameplay.md) §7).

## 1. Типы данных

```ts
type Lang = 'en' | 'ru';

type DictMeta = {
  lang: Lang;
  version: string;              // semver; пиннится в каждом пакете уровней (INV-W4)
  builtAt: string;              // ISO-дата сборки в CI
  sourceHashes: Record<string, string>; // sha256 исходных файлов — воспроизводимость
};

type ValidationDict = {
  meta: DictMeta;
  dawg: Uint8Array;             // DAWG по ключам; EN ~80 тыс. слов, RU ~60 тыс. (03 §5.1)
  displayOverrides: Map<string, string>; // только RU: ключ → каноничная форма с «ё» (03 §2.3)
};

type GenEntry = {
  key: string;                  // нормализованная форма (нижний регистр, RU: ё→е)
  display: string;              // каноничная форма для отрисовки в сетке
  lemmaId: number;              // RU: id леммы OpenCorpora; EN: id базовой формы SCOWL
  zipf: number;                 // частотность (wordfreq / Ляшевская–Шаров, ipm → zipf)
  rank: number;                 // 1..N внутри словаря генерации (1 = самое частое)
  letters: Uint8Array;          // счётчики букв: 26 (EN) / 32 (RU, е=ё) — для мультимножеств
};

type GenerationDict = { meta: DictMeta; entries: GenEntry[] /* отсортированы по rank */ };

type PlacedWord = {
  key: string; display: string; rank: number;
  row: number; col: number; dir: 'H' | 'V';
};

type Level = {
  id: string;                   // '{lang}-{packIdx}-{i}'
  seed: number;                 // fnv1a32('wordgrove:levelgen:v1:{lang}:{dictVersion}:{packIdx}:{i}')
  wheel: string[];              // 5–7 букв (FTUE: 4), перемешаны детерминированно
  grid: { w: number; h: number };            // ≤ 9×9, канва рендера ≥ 5×5 (03 §2.1)
  words: PlacedWord[];          // 3–9 целевых слов
  bonus: string[];              // производный кэш бонус-слов (§3.6, §4.1)
  difficulty: number;           // 0..1 по формуле 03 §6.1
  bucket: 1 | 2 | 3 | 4 | 5;    // D1..D5
  dictVersion: string;
};

type Rng = { next(): number };  // mulberry32 от seed — единый PRNG пайплайна
```

## 2. Контент-пайплайн словарей EN/RU

### 2.1 Источники (по [03](03-core-gameplay.md) §5.1)

| Язык | Словарь валидации (широкий) | Словарь генерации (частотный) | Частотная разметка |
|------|------------------------------|-------------------------------|--------------------|
| EN | ENABLE + SCOWL до size 60 (открытые лицензии), минус списки §2.2 | Топ ~20 тыс. лемм по частотности → **~12 тыс.** после фильтра длины | wordfreq (zipf) |
| RU | Леммы OpenCorpora + контролируемое расширение формами мн. ч. существительных, минус списки §2.2 | Топ ~15 тыс. частотного словаря Ляшевской–Шарова → **~10 тыс.** после фильтра | Ляшевская–Шаров (ipm → zipf) |

Целевые объёмы после фильтра 3–8 букв: EN **~80 тыс.** валидация / ~12 тыс. генерация; RU **~60 тыс.** / ~10 тыс. — коридоры объёмов проверяются assert'ом при сборке (§2.6). Ключевое решение из 03 §5.1 сохранено дословно: **валидация щедрая, генерация строгая** — в сетке только слова, которые знает средний игрок; «его» редкое слово игрока принимается как бонусное.

RU-расширение формами: в валидацию входят леммы и формы мн. ч. существительных как отдельные записи с общим `lemmaId` («стол» и «столы»); генератор использует `lemmaId` для запрета форм-дублей в одной сетке (03 §5.2, шаг 3). Прочие словоформы (падежи, спряжения) в v1.0 не включаются — источник споров и жалоб, решение пересматривается по телеметрии сэмпла вводов (§4.2).

### 2.2 Фильтры

Порядок применения фиксирован; каждый фильтр логирует счётчик отброшенного в отчёт сборки.

| # | Фильтр | Правило | Куда применяется |
|---|--------|---------|------------------|
| F-1 | Длина | 3 ≤ len ≤ 8 (03 §5.1; минимум 3 — 03 §2.3) | валидация + генерация |
| F-2 | Алфавит | только a–z (EN) / а–я (RU); дефисы, апострофы, диакритика, цифры — отказ | валидация + генерация |
| F-3 | Имена собственные и аббревиатуры | EN: словоформы, встречающиеся в источниках только с заглавной; RU: граммемы Name/Surn/Geox/Orgn/Abbr в OpenCorpora | валидация + генерация |
| F-4 | BLACK-список | обсценная лексика, оскорбления, слюры: EN — LDNOOBW + ручные дополнения; RU — корпусный обсценный список + ручные. Слово удаляется отовсюду («в словаре валидации отсутствует», 03 §2.3) | валидация + генерация |
| F-5 | GREY-список | чувствительная лексика (анатомия, болезни, алкоголь, религия): остаётся в валидации (бонус принимается — игрока не «одёргиваем»), но никогда не попадает в сетку и в бонус-примеры UI. Brand-safety для аудитории 45+ ([06](06-monetization.md) §9) | только генерация |
| F-6 | Частотный порог | zipf ≥ порога и попадание в топ-N (EN 20 тыс. / RU 15 тыс.) | только генерация |
| F-7 | Части речи (RU) | генерация: существительные в словарной форме + формы мн. ч.; прилагательные/глаголы — только высокочастотные (топ-5000) | только генерация |

**Нормализация (до всех фильтров):** нижний регистр; RU: `ё → е` в ключе, каноничная форма с «ё» сохраняется в `display` (03 §2.3: «е»=«ё» при вводе, в сетке — каноничная форма). Коллизии ключей после нормализации («все»/«всё») схлопываются в одну запись: `display` — более частотная форма, `zipf` — максимум пары. На колесе буква отображается как «Е» (единая), в сетке слово рендерится через `display`.

### 2.3 Редкость букв (для формулы сложности)

Из словаря генерации считается частота каждой буквы; редкость нормируется логарифмически:

```ts
function rarity(c: Letter, freq: Map<Letter, number>): number {
  const fMax = max(freq.values()), fMin = min(freq.values());
  return clamp01((Math.log(fMax) - Math.log(freq.get(c))) / (Math.log(fMax) - Math.log(fMin)));
}
// Редкие буквы (rarity ≥ 0.7): EN — Q, Z, J, X; RU — Щ, Ф, Ъ, Э (примеры из 03 §6.1: Q/Z/Щ/Ф)
```

Таблица `letterFreq` кладётся в `GenerationDict.meta` — генератор и скоринг сложности используют один источник.

### 2.4 Структура итогового словаря и сериализация

- **Валидация → DAWG** (минимизированный ациклический автомат): проверка `contains(key)` за O(len), размер EN ≈ 250–400 КБ, RU ≈ 220–350 КБ — умещается в бюджет офлайн-бандла ([03](03-core-gameplay.md) §7). Кладётся в клиент.
- **Генерация → JSON-массив `GenEntry`**, отсортированный по `rank`. В клиент НЕ попадает — используется только CI-генератором.
- Обе части подписаны `version`; пакет уровней ссылается на версию словаря, с которой собран (INV-W4). Обновление словаря = новая минорная версия + прогон регресс-теста §2.6 + перегенерация только затронутых бонус-кэшей (сетки не трогаем — см. §4.1 про источник истины).

### 2.5 Псевдокод пайплайна

```ts
async function buildDictionaries(lang: Lang, cfg: PipelineCfg) {
  const raw      = await loadSources(lang, cfg);                    // §2.1, с sha256 в meta
  const norm     = raw.map(e => normalize(lang, e));                // §2.2: регистр, ё→е
  const merged   = mergeByKey(norm);                                // коллизии ключей → одна запись
  const valPool  = merged
    .filter(F1_length).filter(F2_alphabet)
    .filter(F3_properNounsAbbrev)
    .filter(e => !BLACKLIST[lang].has(e.key));                      // F-4
  const genPool  = valPool
    .filter(e => !GREYLIST[lang].has(e.key))                        // F-5
    .filter(e => e.zipf >= cfg.genZipfMin[lang])                    // F-6
    .filter(e => allowedPos(lang, e))                               // F-7
    .sort(byZipfDesc).slice(0, cfg.genTop[lang]);                   // EN 20k / RU 15k
  genPool.forEach((e, i) => { e.rank = i + 1; });

  assertVolumeCorridors(lang, valPool.length, genPool.length);      // §2.6, стоп сборки
  return {
    val: { meta, dawg: buildDawg(valPool), displayOverrides: yoMap(valPool) },
    gen: { meta, entries: genPool },
    report: buildReport(/* счётчики фильтров, топ отброшенных, диффы с прошлой версией */),
  };
}
```

### 2.6 QA словаря (гейт в CI)

- Коридоры объёмов: EN валидация 70–90 тыс., генерация 11–13 тыс.; RU 50–70 тыс. / 9–11 тыс. Выход за коридор — красная сборка (обычно сломался источник или фильтр).
- Регресс-дифф: список слов, ушедших/пришедших относительно прошлой версии; дифф > 2% объёма — ручное ревью лингвиста.
- Смоук BLACK/GREY: контрольный набор из ~200 заведомо запрещённых слов не проходит `contains`; ~50 «спорных» GREY-слов проходят валидацию, но отсутствуют в генерации.
- ё-инварианты (RU): для каждой записи `displayOverrides` ключ получается из display нормализацией; «елка» валидна, в сетке — «ЁЛКА».

## 3. Генератор уровней-кроссвордов

### 3.1 Выбор базового слова и набора букв колеса

Колесо уровня — мультимножество букв базового слова W (03 §5.2, шаг 1): букв 5–7 (FTUE 4), стандартная производственная полоса зрелой игры — **6–7 букв, 4–8 сеточных слов** (баккеты D2–D4). Полосы по баккетам (стартовые значения конфига генератора; калибровка по телеметрии — 03 §6.1):

| Баккет | Букв колеса | Слов сетки | Ранг базового слова | Редких букв (rarity ≥ 0.7) |
|--------|-------------|------------|---------------------|-----------------------------|
| D1 | 5–6 | 3–4 | топ-3000 | 0 |
| D2 | 6 | 4–5 | топ-6000 | ≤ 1 |
| D3 | 6–7 | 5–6 | топ-9000 | ≤ 1 |
| D4 | 7 | 6–8 | топ-12000 (EN) / топ-10000 (RU) | ≤ 2 |
| D5 | 7 | 7–9 | весь словарь генерации | без ограничений |

```ts
function pickBaseWord(gen: GenerationDict, b: Bucket, rng: Rng, used: UsedIndex): GenEntry | null {
  const band = BUCKET_BANDS[b];
  const pool = gen.entries.filter(e =>
    e.key.length >= band.wheelMin && e.key.length <= band.wheelMax &&
    e.rank <= band.maxRank &&
    countRare(e) <= band.maxRare &&
    !used.baseWindow50.has(e.key));            // R-9: база не повторяется в окне 50 уровней
  return pool.length ? pool[Math.floor(rng.next() * pool.length)] : null;
}
```

Полосы — таргетирование; финальный баккет уровню присваивает формула §3.7. Уровень, «уехавший» в соседний баккет, не бракуется — уходит в пул своего фактического баккета (§3.8).

### 3.2 Перечисление кандидатов (мультимножества)

```ts
function enumerateCandidates(W: GenEntry, gen: GenerationDict): GenEntry[] {
  // e — кандидат, если счётчик каждой буквы e ≤ счётчика в W (буквы колеса не «размножаются», INV-W1)
  return gen.entries.filter(e =>
    e.key !== W.key &&
    e.key.length >= 3 &&
    fitsMultiset(e.letters, W.letters));       // 26/32 сравнения счётчиков, O(N)
}
```

Для словаря генерации в 10–12 тыс. записей перебор тривиален (< 5 мс). Отдельно тем же кодом по словарю **валидации** перечисляется полный пул для бонус-кэша (§3.6) — там записей 60–80 тыс., по-прежнему < 100 мс.

### 3.3 Фильтр и жадный отбор слов сетки

Фильтр кандидатов (03 §5.2, шаг 3): частотный ранг ≤ порога баккета; RU — не более одной формы на `lemmaId` в пуле финального отбора («СТОЛ» и «СТОЛЫ» вместе в сетку не кладутся).

```ts
function selectGridWords(W: GenEntry, pool: GenEntry[], b: Bucket, rng: Rng): GenEntry[] {
  const target = randInt(rng, BUCKET_BANDS[b].minWords, BUCKET_BANDS[b].maxWords); // 3..9
  const chosen = [W];                                          // база — всегда якорь сетки
  const lemmas = new Set([W.lemmaId]);
  while (chosen.length < target) {
    const scored = pool
      .filter(c => !chosen.includes(c) && !lemmas.has(c.lemmaId))
      .filter(c => sharesLetter(c, chosen))                    // шаг 4 из 03 §5.2: пересечение обязательно
      .map(c => ({ c, s: 0.4 * (1 - c.rank / pool.length)     // частое — лучше для читаемости
                     + 0.4 * crossPotential(c, chosen) / 8     // разных общих букв с выбранными
                     + 0.2 * c.key.length / 8 }));             // длинное — каркас сетки
    if (!scored.length) break;
    const best = argmaxWithJitter(scored, rng, 0.05);          // джиттер — вариативность при том же сиде базы
    chosen.push(best); lemmas.add(best.lemmaId);
  }
  return chosen.length >= BUCKET_BANDS[b].minWords ? chosen : [];
}
```

### 3.4 Укладка в сетку: жадный порядок + backtracking, скоринг компактности

Слова сортируются: якорь W первым (горизонтально, центр поля 9×9), остальные по убыванию длины. Дальше — поиск с возвратом; на каждом шаге кандидаты-размещения пробуются в порядке убывания скоринга компактности (жадность даёт быстрый успех, backtracking — полноту).

```ts
const K_MAX = 500;                              // бюджет итераций укладки (03 §5.2, шаг 5)

function layoutCrossword(words: GenEntry[], rng: Rng): GridSnapshot | null {
  const g = emptyGrid(9);
  placeAnchor(g, words[0]);                     // горизонталь, центрирование
  let iters = 0;

  function place(i: number): GridSnapshot | null {
    if (i === words.length) return snapshot(g);
    const cands: Placement[] = [];
    for (const cell of g.filledCells())         // каждая буква на поле —
      for (const k of matchingLetters(words[i], cell.letter)) // × каждая совпадающая буква слова
        for (const dir of ['H', 'V'] as const) {
          const p = placementAt(words[i], k, cell, dir);
          if (isLegal(g, p)) cands.push(p);
        }
    cands.sort((a, b2) => compactScore(g, b2) - compactScore(g, a));  // жадный порядок
    for (const p of cands) {
      if (++iters > K_MAX) return null;         // бюджет исчерпан → R-2, другой отбор слов
      apply(g, p);
      const r = place(i + 1);
      if (r) return r;
      undo(g, p);
    }
    return null;                                // на этом уровне не разместить → откат
  }
  return place(1);
}

// Классические правила легальности кроссворда:
function isLegal(g: Grid, p: Placement): boolean {
  return lettersMatchAtCrossings(g, p)          // 1. пересечения совпадают по буквам
    && nonCrossCellsEmpty(g, p)                 // 2. непересечения — на пустых клетках
    && noSideContact(g, p)                      //    и без боковых касаний (иначе случайные раны, INV-W2)
    && cellBefore(g, p).isEmpty && cellAfter(g, p).isEmpty  // 3. пустые клетки до и после слова
    && bboxAfter(g, p).w <= 9 && bboxAfter(g, p).h <= 9;    // 4. bbox ≤ 9×9 (03 §2.1)
}

function compactScore(g: Grid, p: Placement): number {
  return 10 * crossingsOf(p)                    // максимум пересечений — плотный кроссворд
       -  1 * deltaBboxArea(g, p)               // штраф за расползание bounding box
       -  2 * aspectPenalty(g, p);              // |w − h| — тяготеем к квадратной форме
}
```

### 3.5 Критерии отбраковки

| # | Критерий | Реакция |
|---|----------|---------|
| R-1 | Пул кандидатов после фильтра < minWords(баккета) + 2 | другое базовое слово |
| R-2 | Укладка не найдена за K = 500 итераций | другой отбор слов (до 8 попыток), затем другая база (03 §5.2, шаг 5) |
| R-3 | Bbox > 9×9 | гейтится в `isLegal`, сюда не доходит (страховочный assert) |
| R-4 | Плотность `fillRatio` = буквенные клетки / площадь bbox < 0.30 | отбор слов заново — сетка «палочная», некрасивая |
| R-5 | Аспект bbox > 2:1 | отбор слов заново |
| R-6 | Финальный скан: есть ран ≥ 2 клеток, не равный целевому слову | красный assert — по построению невозможно (INV-W2), защита от регрессий |
| R-7 | Финальный скан: любой ран читается как слово BLACK/GREY-списка | брак уровня + алерт в отчёт (03 §2.3: «в сетках не встречается никогда») |
| R-8 | Бонус-слов < 2 | другая база — уровень обязан кормить копилку жёлудей ([05](05-economy.md) §2.2) |
| R-9 | Повтор мультимножества колеса внутри пакета или базы в окне 50 уровней | другая база — вариативность контента |

### 3.6 Бонус-кэш уровня

По 03 §5.2 (шаг 6): все слова словаря **валидации**, составимые из букв W и не попавшие в сетку, пишутся в `bonus`. Назначение кэша — скоринг (ожидаемое число бонус-слов), QA и аналитика; **источником истины в рантайме кэш не является** (§4.1) — иначе каждое обновление словаря требовало бы перегенерации всех пакетов. Сериализация: строка с разделителями, сортировка по ключу; типовой объём 10–60 слов ≈ 100–700 байт — умещается в бюджет 2 КБ на уровень.

### 3.7 Скоринг сложности (дословно [03](03-core-gameplay.md) §6.1)

```ts
function computeDifficulty(W: GenEntry, words: GenEntry[], gen: GenerationDict): number {
  const R = avg([...new Set(W.key)].map(c => rarity(c, gen.meta.letterFreq)));  // R_letters
  const F = avg(words.map(w => w.rank / gen.entries.length));                   // F_words: реже → выше
  const N = clamp01((words.length - 3) / 6);                                    // N_norm: 3 слова → 0, 9 → 1
  const L = clamp01((avg(words.map(w => w.key.length)) - 3) / 4);               // L_norm: 3 → 0, 7 → 1
  return 0.35 * R + 0.30 * F + 0.20 * N + 0.15 * L;
}
// Баккеты (03 §6.1): D1 [0–0.25), D2 [0.25–0.45), D3 [0.45–0.6), D4 [0.6–0.75), D5 [0.75–1]
```

### 3.8 Сортировка уровней по сложности и сборка пакетов

Сгенерированные уровни складываются в пулы по фактическому баккету. Пакет из 100 уровней собирается по целевой кривой 03 §6.2:

```ts
function targetBucket(n: number): Bucket {
  const d = 0.10 + (0.62 - 0.10) * (1 - Math.exp(-n / 120));   // Dmin 0.10, Dmax 0.62 (03 §6.2)
  const saw = [-1, 0, 0, +1, 0, -1, 0, +1, 0, +2][(n - 1) % 10]; // пила: каждый 10-й — пик
  return clampBucket(bucketOf(d) + saw);                        // D1..D5; пик не выше D5
}

function assemblePack(packIdx: number, pools: Pools, rng: Rng): Pack {
  const levels: Level[] = [];
  for (let i = 0; i < 100; i++) {
    const n = packIdx * 100 + i + 1;
    const lvl = drawFromPool(pools[targetBucket(n)], rng, /* соблюдая R-9 */);
    assert(jsonBytes(lvl) <= 2048);                             // 03 §7: уровень ≤ 2 КБ
    levels.push(lvl);
  }
  return { id: packIdx, levels, dictVersion: pools.dictVersion };
}
```

Внутри баккета уровни дополнительно ранжируются по `difficulty` — при DDA-запросе «на 1 баккет ниже» (03 §6.3) клиент берёт верхнюю треть соседнего пула, чтобы просадка ощущалась мягко. Уровни 1–10 не генерируются серийно: FTUE-пак собирается в спецрежиме с ограничениями таблицы 03 §6.4 (4–6 букв, 2–6 слов, гарантированное очевидное бонус-слово на уровнях 2–3) и проходит 100% ручное ревью. Ежедневный премиум-кроссворд 9×9 — полуручной: генератор предлагает, редактор курирует (03 §5.3).

## 4. Валидация бонусных слов в рантайме

### 4.1 Алгоритм проверки ввода

Решение о валидности принимает ТОЛЬКО пара «DAWG валидации + мультимножество колеса»; бонус-кэш уровня — вспомогательный. Расхождение кэша и DAWG (дрейф версий словаря) решается в пользу игрока и логируется.

```ts
type SubmitResult = 'GRID_HIT' | 'BONUS' | 'DUPLICATE' | 'INVALID' | 'TOO_SHORT' | 'NOT_IN_WHEEL';

function submitWord(raw: string, lvl: LevelState, dict: ValidationDict, piggy: Piggy): SubmitResult {
  const key = normalizeInput(lvl.lang, raw);            // нижний регистр; RU: ё→е (03 §2.3)
  if (key.length < 3) return 'TOO_SHORT';               // 03 §2.3
  if (!fitsMultiset(letterCounts(key), lvl.wheelCounts))
    return 'NOT_IN_WHEEL';                              // INV-W1 симметричен на вводе
  if (lvl.foundGrid.has(key) || lvl.foundBonus.has(key))
    return 'DUPLICATE';                                 // нейтральная анимация, без наград (03 §2.1)
  if (lvl.gridWords.has(key)) {
    openGridWord(lvl, key);                             // слово встаёт в кроссворд
    lvl.invalidStreak = 0;
    return 'GRID_HIT';
  }
  if (dawgContains(dict.dawg, key)) {                   // === валидация против ПОЛНОГО словаря ===
    lvl.foundBonus.add(key);
    const grant = Math.min(2, PIGGY_CAP - piggy.amount); // +2 жёлудя; кап 200, переполнение сгорает (05 §2.2)
    piggy.amount += grant;
    if (!lvl.bonusCache.has(key))
      telemetry('dict_drift', { key, dictVersion: dict.meta.version, levelId: lvl.id });
    lvl.invalidStreak = 0;
    return 'BONUS';
  }
  lvl.invalidStreak++;                                  // 5 невалидных подряд → оффер RV-1 (03 §3)
  return 'INVALID';                                     // мягкая тряска колеса, без штрафа
}
```

### 4.2 Пограничные случаи

- **ё/е (RU):** ввод «елка» и «ёлка» — один ключ; в сетке рендерится `display` («ЁЛКА»); на колесе — единая «Е».
- **Слово сетки, ещё не открытое, введено повторно после открытия подсказкой:** `DUPLICATE` — подсказка «открывает» слово наравне с вводом (03 §2.5).
- **Пары вложенных слов** («СТО» в сетке, «СТОЛ» бонус) — независимые ключи, оба валидны; никакой префиксной блокировки.
- **Офлайн:** все проверки локальны по DAWG из бандла — ядро работает при 0% сети (03 §7).
- **Телеметрия вводов:** каждый ввод НЕ трекается (шумно); сэмпл 10% уходит в отдельный поток тюнинга словаря ([09](09-analytics-kpi.md) §1.4). Событие `dict_drift` — всегда.
- **Антифарм жёлудей:** награда только за первое нахождение ключа за уровень; кап копилки 200 ограничивает выгоду фарма структурно (05 §2.2), отдельного лимита бонус-слов не требуется.

## 5. QA контента и телеметрическая петля

### 5.1 Автотесты пайплайна (CI, каждый merge — [10](10-production.md) §7)

1. INV-W1: для каждого уровня каждого пакета — все `words` и `bonus` проходят `fitsMultiset`.
2. INV-W2: скан ранов — каждый максимальный ран ≥ 2 равен ровно одному слову; связность; bbox ≤ 9×9.
3. INV-W3: пересечение множества слов сетки с BLACK ∪ GREY пусто; `bonus` не содержит BLACK.
4. INV-W4: повторная генерация пакета из тех же сидов даёт байт-в-байт тот же JSON.
5. Размеры: JSON уровня ≤ 2 КБ; в бандле ≥ 200 уровней (03 §7).
6. Перф-бюджет: пакет 100 уровней собирается < 10 мин в CI (DoD Прохода А, [10](10-production.md) §3).

### 5.2 Расчётные коридоры solve-time (нормативные для DoD и телеметрии)

| Баккет | p50 расчётный | Коридор ±25% (DoD Прохода А) |
|--------|---------------|------------------------------|
| D1 | 60 с | 45–75 с |
| D2 | 95 с | 71–119 с |
| D3 | 140 с | 105–175 с |
| D4 | 200 с | 150–250 с |
| D5 (пики) | 290 с | 218–363 с |

Сходимость с книгой: пиковые уровни ≈ ×2 к среднему баккету (05 §7, п.1: «solve-time ×2»); 6 уровней/день D15+ × ~140–200 с + daily ≈ 20 мин/день на 2–3 сессии по 8–12 мин (03 §4). Эти же коридоры использует симулятор экономики ([12](12-economy-sim.md) §2.2).

### 5.3 Телеметрия как QA (03 §5.3)

- Уровень с фактическим solve-time p50 вне коридора §5.2 ИЛИ completion < 92% → автоматический отчёт на переделку (событие `level_finish`, [09](09-analytics-kpi.md) §1.1).
- Ручное сэмплирование лингвистом: 5% уровней каждого пакета, 100% ежедневных премиум-кроссвордов.
- Дрейф словаря: всплеск `dict_drift` > 0.1% вводов — сигнал рассинхрона версий пакетов и DAWG.

## 6. Границы конфигурации

- **Зашито в контент (офлайн, меняется перегенерацией):** слова, укладка, difficulty, баккет, бонус-кэш.
- **Remote config (рантайм):** параметры DDA (03 §6.3), порядок выдачи пакетов, версия активного словаря, флаг телеметрии сэмпла вводов.
- Правка формулы сложности или полос §3.1 = новая версия генератора → перегенерация будущих пакетов; уже выданные игрокам пакеты не переписываются (честность прогресса и сравнимость A/B, 03 §5.2).
