# Технологический стек

[⌂ Вики](../../README.md) · [Позиции](../README.md) · [Платформа](README.md) · Технологический стек

Страница отделяет технологии, **названные в тексте вакансии**, от **вероятного стека** — того, что почти неизбежно используется под такие задачи, но в объявлении буквально не упомянуто.

## Явно упомянуто в вакансии

Вакансия Platform сформулирована через *возможности и области ответственности*, а не через конкретные продукты. Никакие конкретные фреймворки, языки или сервисы в ней прямо не названы. Единственные «твёрдые» технические ориентиры — это сами понятия из текста:

- **Identity systems** — системы идентификации для организаций и агентов.
- **Platform API infrastructure** — API-инфраструктура платформы.
- **Usage-based tracking / billing integrations / seat provisioning** — учёт по потреблению, интеграции биллинга, выдача мест.
- **Data retention / audit logging / compliance controls** — хранение данных, аудит-логирование, контроли комплаенса.
- **Security и workload isolation** поверх **large-scale storage and compute** — безопасность и изоляция нагрузок поверх крупномасштабного хранилища и вычислений.

> **Оговорка.** Всё, что ниже, — реконструкция по индустриальным стандартам для многопользовательских (multi-tenant) платформ; это **не** заявление компании и не цитаты из вакансии.

## Вероятный стек (аналитическая реконструкция)

Ниже — технологии, которые *с высокой вероятностью* стоят за описанными задачами.

**Идентификация и доступ**
- Протоколы и стандарты AuthN/AuthZ: **OAuth 2.0 / OIDC**, **SAML** для SSO; **JWT**-токены; RBAC/ABAC-модели прав — *вероятный* набор для identity.
- Каталоги/провайдеры идентичности и service accounts для машинных субъектов (агентов) — *реконструкция*.

**API-инфраструктура**
- **REST** и/или **gRPC**, возможно **GraphQL**; API-шлюз (API gateway), rate limiting, версионирование — *вероятно*.

**Биллинг и учёт потребления**
- Внешние биллинг-провайдеры (класс **Stripe** / metering-платформы) для инвойсинга и подписок — *реконструкция*.
- Конвейеры событий потребления (event streaming, напр. **Kafka**-класс) и агрегация metering-данных — *вероятно*.

**Данные, аудит, комплаенс**
- Реляционные и/или объектные хранилища для данных и аудит-логов; неизменяемое (append-only / tamper-evident) хранение логов — *реконструкция*.
- Шифрование в покое и в передаче (**TLS**, KMS-класс управления ключами) — *вероятно*, особенно для регулируемых данных.

**Изоляция и безопасность**
- Механизмы tenant-изоляции поверх хранилища и compute; сетевые/ресурсные границы (стыкуется с механизмами [Инфраструктуры](../10-infrastructure/README.md): контейнеры, namespaces, network policies) — *реконструкция*.
- Секрет-менеджмент (Vault-класс), политики least privilege — *вероятно*.

**Инфраструктура-основа**
- **Kubernetes** и мульти-облако как субстрат (по аналогии с соседней ролью Infrastructure, где Kubernetes назван прямо; в вакансии Platform — *не* назван) — *реконструкция*.
- Infrastructure-as-Code (**Terraform**-класс), наблюдаемость (Prometheus/Grafana/OpenTelemetry-класс) — *вероятно*.

**Языки**
- *Вероятно* Go и/или Python для платформенных сервисов; TypeScript — *возможно* на API/продуктовой границе. Не заявлено.
