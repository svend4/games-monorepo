# Технологический стек

[⌂ Вики](../../README.md) · [Позиции](../README.md) · [Agent Harness](README.md) · Технологический стек

Страница разделяет технологии, **названные в тексте вакансии**, и **аналитическую реконструкцию** вероятного стека. Для роли Agent Harness важна честность: текст вакансии почти не называет конкретных инструментов, поэтому большая часть стека — реконструкция.

## Явно упомянуто в вакансии

Текст вакансии Agent Harness описан на уровне **архитектурных областей**, а не конкретных библиотек. Прямо названы концепции, а не продукты:

- **agent loop architecture** — архитектура цикла агента;
- **tool integrations** — интеграции инструментов;
- **prompt scaffolding** — промпт-каркас;
- **execution environments** — окружения исполнения;
- **capability primitives** — примитивы возможностей;
- **orchestration systems** — системы оркестрации (memory, state management, multi-agent coordination, task decomposition);
- **guardrails / reliability mechanisms** — ограждения и механизмы надёжности;
- **extension layer** к external tools, APIs, environments;
- **evaluation / observability tooling** — оценка и наблюдаемость.

> Конкретные фреймворки, языки или инфраструктурные продукты в тексте вакансии **не названы**. Всё в следующем разделе — реконструкция.

## Вероятный стек (аналитическая реконструкция)

*Пометка: раздел — обоснованные предположения на основе описанных задач и общепринятой практики построения агентных систем; в тексте вакансии этого нет.*

- **Языки (вероятно):** Python как основной язык агентной обвязки и интеграции с ML; возможно Go/Rust для высоконагруженных компонентов оркестрации и надёжности.
- **Работа с моделями (вероятно):** взаимодействие с фронтир-LLM через API/inference-слой; форматы вызова инструментов (tool/function calling); структурированный вывод (structured output).
- **Оркестрация и масштабирование (вероятно):** контейнеризация (Docker) и Kubernetes для горизонтального масштабирования агентов; очереди задач и брокеры сообщений для координации; хранилища состояния (например, key-value или базы данных) для state management и памяти.
- **Окружения исполнения (вероятно):** изолированные sandbox-среды/контейнеры для безопасного запуска кода агента.
- **Наблюдаемость (вероятно):** распределённая трассировка (distributed tracing) и метрики (например, OpenTelemetry-подобные подходы); системы логирования и дашбордов для разбора агентных сессий.
- **Оценка (вероятно):** внутренние eval-фреймворки — наборы задач-бенчмарков и harness для воспроизводимого прогона.
- **Инфраструктура (косвенно следует):** доступ к крупному GPU-кластеру (в раунде — крупная инвестиция от NVIDIA), поскольку агенты обслуживают ИИ-R&D с большими вычислениями.

*Все конкретные названия выше приведены как типичные представители класса технологий, а не как подтверждённый выбор Mirendil.*
