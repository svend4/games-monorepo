# Технологический стек

[⌂ Вики](../../README.md) · [Позиции](../README.md) · [Post-Training: RL](README.md) · Технологический стек

Важно: сама вакансия Post-Training, RL **не перечисляет конкретных библиотек и фреймворков**. Она описывает области работы (RL/SFT/дистилляция, масштабирование, верификация, инфраструктура), но не называет инструменты. Поэтому «явный» раздел ниже фиксирует лишь то, что прямо следует из текста, а конкретные технологии вынесены в реконструкцию и помечены соответствующе.

## Явно упомянуто в вакансии

Дословно из текста называются не продукты, а функциональные компоненты стека:

- **Пост-тренинг-стек** (post-training stack) для фронтир-моделей рассуждения.
- **Методы обучения:** RL, SFT, дистилляция (distillation).
- **Генерация роллаутов** (rollout generation) и **фильтрация** (filtering) данных.
- **Пайплайны верификации** (verification pipelines).
- **Инфраструктура для крупномасштабных экспериментов** и работа с командами **systems / infra / data** до продакшн-масштаба.
- **Off-policy / асинхронное обучение** как режим работы контура.

То есть на уровне вакансии «стек» — это набор функций (обучение, генерация, верификация, инфраструктура), а не конкретный список тулинга.

## Вероятный стек (аналитическая реконструкция)

Ниже — обоснованное предположение о конкретных технологиях, исходя из описанных задач и распространённых практик фронтир-лабораторий. Это **аналитическая реконструкция**, вакансия этих названий не содержит.

- **Фреймворки обучения:** PyTorch (наиболее вероятно) и/или JAX для крупномасштабного обучения; распределённые обёртки для тренировки на многих ускорителях.
- **RL-контур для LLM:** реализация policy-gradient методов (вероятно PPO/GRPO-семейство) поверх кастомного или открытого RL-стека для языковых моделей.
- **Инференс для генерации роллаутов:** высокопроизводительные движки инференса (inference) — вероятно из ряда vLLM / SGLang / TensorRT-LLM — для быстрой генерации ответов, на которых считается награда.
- **Ускорение и память:** CUDA, техники вроде KV-кэша (KV-cache), возможно квантизация (quantization) и спекулятивное декодирование (speculative decoding) на стороне генерации.
- **Оркестрация и инфраструктура:** Kubernetes и/или планировщики кластерного уровня, распределённое хранилище датасетов, системы экспериментального трекинга и логирования.
- **Аппаратная база:** GPU-кластеры (в раунде участвовала NVIDIA — вероятен акцент на NVIDIA-стеке), с расчётом на масштабирование по мере роста компании.

> Оговорка: конкретные названия — вывод из типовых практик отрасли и характера задач, а не подтверждённый факт о внутреннем стеке Mirendil. Компания на момент анонса не публиковала технических деталей.
