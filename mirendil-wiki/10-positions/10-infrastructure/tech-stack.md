# Технологический стек

[⌂ Вики](../../README.md) · [Позиции](../README.md) · [Инфраструктура](README.md) · Технологический стек

Страница отделяет технологии, **названные в тексте вакансии**, от **вероятного стека** — того, что почти неизбежно используется под такие задачи, но в объявлении буквально не упомянуто.

## Явно упомянуто в вакансии

Вакансия называет немного конкретных технологий; там, где называет, — это в основном инференс-слой:

- **Kubernetes** — прямо в названии области «Kubernetes and multi-cluster compute». Базовый оркестратор (orchestrator) для CPU/GPU-кластеров.
- **Движки инференса (inference engines):** **vLLM**, **SGLang**, **TensorRT-LLM** — названы как инструменты обслуживания моделей.
- **Оптимизации инференса:** **KV-cache**, **speculative decoding**, **квантизация (quantization)** — названы как техники ускорения/уплотнения инференса.

> **Оговорка.** Кроме Kubernetes и перечисленных инференс-технологий, вакансия описывает области *концептуально* (scheduling, autoscaling, routing, peering, checkpointing и т.д.), не привязывая их к конкретным продуктам. Всё остальное ниже — реконструкция.

## Вероятный стек (аналитическая реконструкция)

Ниже — технологии, которые *с высокой вероятностью* стоят за описанными задачами. Это **реконструкция** по индустриальным стандартам для фронтир-ML-инфраструктуры, а не заявление компании.

**Оркестрация и планирование**
- Kubernetes + GPU-планировщики/очереди — *вероятно* что-то из класса Volcano / Kueue / Slurm для gang-scheduling и батч-очередей.
- Cluster autoscaler, custom scheduling под GPU-топологию — *реконструкция*.

**Обучение (training)**
- **PyTorch** (и/или **JAX**) как основной фреймворк — *вероятно*.
- **CUDA**, **NCCL** для GPU-вычислений и межузловых коллективов — *косвенно следует* из распределённого обучения.
- Библиотеки распределённого обучения (data/tensor/pipeline-параллелизм) — *реконструкция*.

**Изоляция и sandboxing**
- Контейнеры (**Docker/OCI**, **containerd**), микро-VM (**Firecracker**, **gVisor**), **seccomp**, namespaces/cgroups — *вероятный* набор механизмов изоляции.

**Сеть**
- **CNI**-плагины (напр. Cilium/eBPF), network policies, service mesh, L4/L7-балансировщики, VPC-peering/private interconnect между облаками — *реконструкция*.

**Облака и IaC**
- Мульти-облако (напр. AWS/GCP/собственные GPU-провайдеры) — прямо следует из «across clouds»; конкретные провайдеры не названы.
- Infrastructure-as-Code (**Terraform**/подобное), GitOps — *вероятно*.

**Наблюдаемость и состояние**
- Метрики/логи/трейсинг (Prometheus/Grafana/OpenTelemetry-класс) — *вероятно*.
- Надёжное хранилище состояния/чекпоинтов (объектное хранилище, БД) — *реконструкция* под задачу long-running agents.

**Языки**
- *Вероятно* Go и/или Python для платформенных сервисов; Rust — *возможно* для чувствительных к производительности/изоляции компонентов. Не заявлено.
