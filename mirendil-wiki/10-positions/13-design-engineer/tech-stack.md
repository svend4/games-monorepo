# Технологический стек

[⌂ Вики](../../README.md) · [Позиции](../README.md) · [Дизайн-инженер](README.md) · Технологический стек

Страница отделяет то, что **явно названо в вакансии**, от **вероятного стека** — обоснованной реконструкции по смыслу роли и общей практике отрасли.

## Явно упомянуто в вакансии

Текст вакансии Design Engineer **не называет конкретных технологий, языков или фреймворков**. Он описывает зоны ответственности (понимание процессов и абстракции, быстрая итерация, связность, проектирование интерфейсов, AI-native паттерны, качество опыта), но не технологический стек.

> Поэтому всё, что перечислено ниже, — реконструкция. Ни один пункт нельзя цитировать как факт из вакансии.

*Для сравнения:* другие, более технически специфичные вакансии Mirendil (например по инференсу, inference) прямо называют инструменты вроде vLLM, SGLang, TensorRT-LLM, а также квантизацию (quantization), KV-cache и спекулятивное декодирование (speculative decoding). Для роли Design Engineer подобного явного списка в тексте нет.

## Вероятный стек (аналитическая реконструкция)

Ниже — обоснованные предположения по типу работы; помечены как реконструкция.

**Фронтенд и интерфейсный слой** *(реконструкция)*
- TypeScript — основной язык интерфейсного кода.
- React (или аналогичный компонентный фреймворк) — построение UI из переиспользуемых компонентов.
- Дизайн-система (design system) и библиотека компонентов; вероятно инструменты вроде Tailwind CSS или CSS-in-JS для стилей.
- Инструменты потоковой выдачи (streaming UI) для отображения ответов и рассуждений модели в реальном времени.

**Дизайн и прототипирование** *(реконструкция)*
- Figma или аналог для макетов и быстрых прототипов.
- Прототипирование прямо в коде — учитывая связку «design, build and iterate» в одном лице.

**Связь с моделью и бэкендом** *(реконструкция)*
- Клиентский слой к API модели/обвязки (harness): REST и/или gRPC, работа с потоковыми ответами (streaming), инструментами и вызовами агента (tool calls).
- Бэкенд-«клей» на Python и/или TypeScript/Go для продуктовых сервисов между интерфейсом и ядром.

**Инфраструктура разработки** *(реконструкция)*
- Сборка и типизация фронтенда (Vite/Next.js, ESLint, TypeScript-тулинг).
- Наблюдаемость продуктового слоя: логи, метрики использования, трассировка (tracing).

**Оговорка.** *Реконструкция:* конкретный набор зависит от внутренних решений Mirendil, которые публично не раскрыты. Список отражает типичную практику фронтир-ИИ-компаний для продуктово-интерфейсной роли, а не подтверждённый выбор компании.
