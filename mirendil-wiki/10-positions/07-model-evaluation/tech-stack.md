# Технологический стек

[⌂ Вики](../../README.md) · [Позиции](../README.md) · [Оценка моделей](README.md) · Технологический стек

> **Важная оговорка.** Вакансия на роль «Model Evaluation» **не называет конкретных технологий** — она описывает задачи (фреймворки, пайплайны, детекция регрессий, наблюдаемость), но не инструменты. Поэтому раздел «Явно упомянуто» здесь фактически пуст, а весь конкретный стек ниже — **аналитическая реконструкция** по характеру задач и по индустриальной практике. Ничего из перечня нельзя считать подтверждённым для Mirendil.

## Явно упомянуто в вакансии

- **Конкретные технологии не названы.** В тексте фигурируют только классы задач и способностей: evaluation frameworks, automated eval pipelines, regression-detection systems, agent-assisted workflows, observability tooling, взаимодействие с post-training и RL.
- Единственное, что явно вытекает из формулировок как требование к системе, а не к инструменту: непрерывность прогонов («run continuously») и быстрый сигнал («surface signal quickly»).

*(Для сравнения: в некоторых других вакансиях Mirendil — например, по инференсу — стек назван прямо: vLLM, SGLang, TensorRT-LLM, квантизация, KV-cache, speculative decoding. В данной вакансии такого перечня нет.)*

## Вероятный стек (аналитическая реконструкция)

Ниже — **реконструкция**: обоснованные предположения по типовой практике фронтир-лабораторий для задач оценки. Не факты о Mirendil.

- **Реконструкция — ML-фреймворки:** PyTorch и/или JAX для загрузки моделей, прогонов и, при необходимости, вычисления метрик на уровне модели.
- **Реконструкция — инференс для прогонов оценки:** движки высокопроизводительного инференса (vLLM, SGLang, TensorRT-LLM) для быстрой массовой генерации ответов на задачах оценки.
- **Реконструкция — оркестрация и масштаб:** Kubernetes и/или планировщик кластеров (например, Slurm-подобные системы), очереди задач и оркестраторы пайплайнов для непрерывных прогонов.
- **Реконструкция — хранение и учёт результатов:** базы данных/хранилища для истории метрик и артефактов, системы трекинга экспериментов (experiment tracking) для привязки метрик к чекпоинтам и рецептам.
- **Реконструкция — наблюдаемость (observability):** метрики и временные ряды, дашборды, логирование; статистические инструменты для отделения реального сдвига от шума при детекции регрессий.
- **Реконструкция — инфраструктурный слой:** CUDA/ускорители (GPU), скорее всего с участием NVIDIA-стека, учитывая, что NVIDIA — крупный инвестор компании (это факт про инвестора, но не про их внутренний стек).
- **Реконструкция — язык и код:** Python как основной язык оценочной инфраструктуры; возможно, вспомогательные сервисы на других языках.
