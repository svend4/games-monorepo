# Фреймворки оценки за пределами бенчмарков

[⌂ Вики](../../../README.md) · [Позиции](../../README.md) · [Оценка моделей](../README.md) · Фреймворки оценки

## Источник (дословно)

> Design and build evaluation frameworks that measure model capabilities along realistic axes, beyond standard benchmarks.

## Что это простыми словами

Стандартные бенчмарки (benchmarks) — это готовые наборы задач с известными ответами (например, тесты на школьную математику или общие знания). Они удобны для сравнения моделей между собой, но плохо отражают то, ради чего Mirendil вообще строит модель: способность вести реальный ИИ-R&D — придумывать эксперименты, отлаживать обучение, оценивать результаты. Задача этой роли — построить систему измерения способностей модели по «реалистичным осям» (realistic axes), то есть по тем свойствам, которые важны для настоящей исследовательской работы, а не только для прохождения тестов.

## Что конкретно делает инженер

- Проектирует набор оценок (evaluation suite), где задачи имитируют реальные шаги исследовательского цикла: чтение результата эксперимента, формулировка гипотезы, выбор гиперпараметров (hyperparameters), интерпретация метрик обучения.
- Задаёт «оси способностей» (capability axes) — измеримые измерения (например, надёжность рассуждения, устойчивость к длинному контексту, качество планирования многошаговых действий) и способы их количественной оценки.
- Строит рубрики и способы разметки результатов (grading): автоматические проверки, оценку через модель-судью (LLM-as-a-judge), эталонные ответы, где они применимы.
- Заботится о валидности оценки: чтобы метрика измеряла именно то, что заявлено, и не «протекала» через утечку данных (data contamination) из обучающей выборки.
- Документирует, что означает рост или падение по каждой оси, чтобы исследователи могли принимать решения, а не просто смотреть на число.

## Зачем это Mirendil

Тезис компании — «self-accelerating AI»: модель, которая сама экспертна в ИИ-исследованиях и ускоряет собственное развитие. Чтобы такой цикл работал, нужна честная линейка (аналитическая реконструкция), по которой видно, что модель становится лучше именно в исследовательских навыках, а не просто набирает очки на популярных тестах. Стандартные бенчмарки для этого недостаточны — они насыщаются (saturate) и легко «переобучаются» под них. Поэтому собственные фреймворки оценки — фундамент, без которого нельзя понять, приближается ли компания к цели. Это прямо перекликается со словами CEO о «направлении системы под конкретный угол и быстром улучшении»: чтобы направлять, нужно уметь измерять правильную ось.

## Термины

- **Бенчмарк (benchmark)** — фиксированный набор задач с известными ответами для сравнения моделей.
- **Capability axis (ось способности)** — измеримое измерение поведения модели, вдоль которого оценивается прогресс.
- **LLM-as-a-judge (модель-судья)** — использование отдельной модели для оценки качества ответов другой модели.
- **Data contamination (утечка данных)** — попадание тестовых примеров в обучающую выборку, из-за чего оценка завышена.
- **Saturation (насыщение)** — состояние, когда бенчмарк перестаёт различать модели, потому что почти все набирают максимум.
