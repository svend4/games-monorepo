# Технологический стек

[⌂ Вики](../../README.md) · [Позиции](../README.md) · [AI for AI Systems](README.md) · Технологический стек

Ниже стек разделён на то, что **прямо названо или прямо подразумевается формулировками вакансии**, и на **аналитическую реконструкцию** — типичный для такой роли инструментарий, о котором вакансия молчит.

## Явно упомянуто в вакансии

Вакансия не перечисляет конкретные библиотеки поимённо, но её формулировки прямо задают классы технологий:

- **Инференс-системы (inference / serving).** Пункт «Optimize training and inference systems … throughput, memory, and cost … serving» задаёт целый класс движков обслуживания моделей. Индустриальный стандарт для этого класса:
  - **vLLM** — высокопроизводительный сервинг LLM с эффективным управлением KV-кэшем (KV-cache).
  - **SGLang** — движок сервинга с оптимизацией сложных промптов и структурированной генерации.
  - **TensorRT-LLM** — оптимизированный инференс на GPU NVIDIA.
- **Приёмы оптимизации инференса** (следуют из требования снижать память и стоимость):
  - **Квантизация (quantization)** — снижение битности весов/активаций.
  - **Работа с KV-кэшем (KV-cache)** — переиспользование ключей/значений внимания при генерации.
  - **Спекулятивное декодирование (speculative decoding)** — ускорение генерации черновиком от малой модели.
- **Распределённое обучение (distributed training).** Пункт про профилирование распределённого обучения задаёт класс инструментов параллелизма (тензорного, конвейерного, data-параллелизма) и профилировщиков.
- **Оценка и наблюдаемость (evaluation / observability).** Пункт «benchmarks, automated evals, and monitoring» задаёт класс eval-фреймворков и систем мониторинга.

> **Оговорка:** конкретные продукты выше (vLLM, SGLang, TensorRT-LLM) — индустриальный стандарт для названных в вакансии *классов* задач, а не поимённо подтверждённый Mirendil стек. Точный внутренний инструментарий компания публично не раскрывала.

## Вероятный стек (аналитическая реконструкция)

**Это реконструкция** — типовой набор для роли такого профиля во фронтир-лаборатории; поимённо Mirendil его не публиковала.

- **ML-фреймворки:** PyTorch и/или JAX — основные среды обучения фронтир-моделей.
- **GPU-программирование:** CUDA, возможно Triton — для кастомных ядер и оптимизации.
- **Распределённое обучение:** библиотеки параллелизма (FSDP, DeepSpeed, Megatron-стиль) для тензорного/конвейерного/data-параллелизма.
- **Оркестрация и инфраструктура:** Kubernetes, планировщики задач на кластере, системы управления экспериментами и очередями прогонов.
- **Данные:** конвейеры курирования данных (data curation), хранилища и форматы для больших датасетов.
- **Оценка и трекинг:** eval-фреймворки, трекеры экспериментов (типа Weights & Biases-класса), дашборды мониторинга.
- **Агенты и автоматизация:** внутренние фреймворки для LLM-агентов, автоматизирующих ML-цикл (сам продукт Mirendil — платформа для ИИ-R&D, поэтому часть «стека» вероятно собственная).
- **Языки:** Python как основной; C++/CUDA для перф-критичных участков. *Реконструкция.*
