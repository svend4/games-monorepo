# Безопасные sandbox-среды для ИИ-кода

[⌂ Вики](../../../README.md) · [Позиции](../../README.md) · [Инженер по безопасности](../README.md) · Безопасные sandbox-среды для ИИ-кода

## Источник (дословно)

> Build secure sandboxed execution environments for AI-generated code and agentic workflows

## Что это простыми словами

Продукт Mirendil предполагает, что ИИ сам пишет и запускает код — например, чтобы поставить эксперимент, перебрать гиперпараметры или проверить гипотезу. Такой код нельзя выполнять напрямую на боевой инфраструктуре: он может быть ошибочным, а в худшем случае — вредоносным или ведущим себя непредсказуемо. Sandbox (изолированная песочница) — это «стеклянная комната», где ИИ-сгенерированный код (AI-generated code) и агентные воркфлоу (agentic workflows) исполняются, ничего не задевая снаружи.

## Что конкретно делает инженер

- Строит изолированные среды выполнения: контейнеры с усиленной изоляцией (например, gVisor/Firecracker-класса microVM), ограничение системных вызовов (seccomp), namespaces и cgroups.
- Задаёт лимиты ресурсов (CPU, память, время, диск) и запрет или строгий контроль сетевого доступа изнутри песочницы (network egress control).
- Проектирует эфемерность: одноразовые окружения, которые создаются под задачу и уничтожаются после, без сохранения состояния между запусками.
- Внедряет мониторинг поведения кода внутри sandbox: логирование действий, детект попыток выхода за границы (sandbox escape).
- Обеспечивает безопасную передачу входов/результатов между песочницей и платформой без канала для утечки или инъекции.

## Зачем это Mirendil

Это несущий элемент продукта, а не сопутствующая мера. Машина self-accelerating AI по определению запускает машинно-сгенерированный код в цикле «эксперимент → оценка → дообучение»; без безопасного и масштабируемого исполнения этот цикл нельзя ни автоматизировать, ни открыть внешним пользователям «vibe research». *Аналитическая реконструкция:* именно здесь абстрактный «oversight» (надзор за действиями ИИ), который Mirendil называет решаемой инженерной задачей, превращается в конкретный технический контроль — границы того, что исполняемый ИИ-код физически может сделать. Сжать месяцы исследований до дней автоматических итераций реально лишь тогда, когда каждую итерацию можно безопасно и дёшево запускать тысячи раз.

## Термины

- **Sandbox (песочница)** — изолированная среда, где код выполняется без доступа к остальной системе.
- **microVM** — облегчённая виртуальная машина с быстрым стартом и сильной изоляцией (например, Firecracker).
- **seccomp** — механизм ядра Linux для ограничения набора доступных системных вызовов процессу.
- **Sandbox escape** — уязвимость, позволяющая коду вырваться из песочницы в основную систему.
- **Агентный воркфлоу (agentic workflow)** — последовательность действий, которую ИИ-агент выполняет самостоятельно, включая запуск кода и вызов инструментов.
