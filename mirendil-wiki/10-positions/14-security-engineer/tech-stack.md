# Технологический стек

[⌂ Вики](../../README.md) · [Позиции](../README.md) · [Инженер по безопасности](README.md) · Технологический стек

Страница разделяет то, что **явно упомянуто** в тексте вакансии, и **аналитическую реконструкцию** вероятного стека. Важно: вакансия Security Engineer конкретных технологий и продуктов почти не называет — в отличие, например, от вакансии по инференсу (inference), где явно перечислены vLLM, SGLang, TensorRT-LLM, квантизация (quantization), KV-cache, speculative decoding. Поэтому раздел «явно упомянуто» здесь короткий, а бо́льшая часть стека — обоснованная реконструкция.

## Явно упомянуто в вакансии

Вакансия задаёт не инструменты, а **предметные области и типы систем**:

- **Cloud infrastructure** — облачная инфраструктура (конкретный провайдер не назван).
- **ML systems** — ML-системы (обучение, инференс, оценка моделей).
- **Product surfaces** — продуктовые поверхности (интерфейсы, API).
- **Secret management** — управление секретами.
- **Identity verification** — проверка идентичности.
- **Sandboxed execution environments** — изолированные среды выполнения для ИИ-кода и агентных воркфлоу.
- **Frameworks для AI agent ↔ external tools** — каркасы взаимодействия агентов с внешними системами и инструментами.

Конкретные названия продуктов/библиотек в тексте отсутствуют.

## Вероятный стек (аналитическая реконструкция)

Ниже — обоснованные предположения на основе задач роли и типового стека фронтир-ИИ-компании. Всё в этом разделе — *реконструкция*, а не факт из вакансии.

- **Облако и оркестрация:** крупный публичный клауд (AWS/GCP), Kubernetes для оркестрации, инфраструктура как код (Terraform). Обоснование: работа across cloud infrastructure и масштаб ML-экспериментов (*реконструкция*).
- **Изоляция выполнения:** контейнеры (Docker/containerd) с усиленной изоляцией — gVisor, Firecracker/microVM, seccomp, namespaces, cgroups. Обоснование: прямое требование строить secure sandbox для ИИ-кода (*реконструкция*).
- **Секреты и идентичность:** secret-хранилище (класс HashiCorp Vault / cloud KMS), SSO/OIDC, mTLS между сервисами, кратко-живущие сертификаты. Обоснование: пункты про secret management и identity verification (*реконструкция*).
- **ML-платформа рядом:** PyTorch/JAX, CUDA, распределённое обучение — не как зона самого security-инженера, но как окружение, чьи веса и датасеты он защищает. Обоснование: «training our own models end-to-end» и защита model weights/training datasets (*реконструкция*).
- **Наблюдаемость и аудит:** централизованные логи, SIEM/детект аномалий, неизменяемые audit logs действий агентов. Обоснование: требования к трассируемости и реагированию (*реконструкция*).
- **Агентный слой:** посреднический шлюз для tool-use, валидация ввода против prompt injection, allowlist/denylist операций. Обоснование: пункт про frameworks для agent-interactions (*реконструкция*).

> Оговорка: без публичных технических деталей и бенчмарков от Mirendil (на момент анонса их нет) конкретные инструменты не подтверждены. Список отражает типовые решения под названные задачи, а не заявления компании.
